## 운영 적용

사용자 승인으로 공식 interactive-ref 설치기를 실행했다. 운영 Brain의 기존 `c321bf02`에서 먼저 `b148ea56`으로 갱신한 뒤 스캔 복구 본체와 통합 시험 격리가 반영된 `b4e088c0`으로 올렸다. 각 설치의 종료 코드는 0이며 최종 설치 기록과 운영 app HEAD가 일치한다. DB 스키마는 48이고 두 번째 설치에서 새 migration은 없었다. doctor가 DB·데몬 정상과 Codex `scan-only`를 확인했다. 사용자 hook·notify 설정과 배포 플러그인 ref를 바꾸지 않았다. 설치본이 배포 플러그인보다 앞서 `PLUGIN_BEHIND`가 표시되며, 기존 Garmin 패키지 충돌 경고도 관측됐다.

## 실제 기록 검증

- 초기 메타 검사부터 원본 파일을 변경하지 않았다. 한 파일의 완결 세션 메타 ID가 서로 다른 파일 5개는 귀속을 확정할 수 없어 보존·제외했다. 나머지는 제품의 명시 수집 명령으로 초기 수집했다. 대화가 없는 21개 파일은 유효 메타와 수집 이력이 있어도 저장 세션의 분모에서 제외했다.
- 최초 명시 수집과 추가 스냅샷의 비교 가능한 세션 2,629개가 DB와 일치했다. 시작 폴더는 2,629개 모두 최초 메타와 일치했다. 프로젝트·워크트리 태그가 각각 2,563개 있었다.
- 최종 스냅샷의 실제 JSONL은 2,663개였다. 메타 ID가 유효한 2,658개에서 대화가 없는 21개를 구분하니 비교 가능한 세션은 2,637개였다. DB의 Codex 세션 ID 집합과 정확히 일치했다. 파일 간 상이 내용 ID 충돌, 누락 ID, DB에만 있는 ID는 각각 0개다. 자식 세션 798개와 보관 세션 3개가 포함된다.
- 실제 세션 읽기 5개, 대화 검색 3개, 가림 패턴이 포함된 실제 메시지 3개를 원문이나 민감한 값의 출력 없이 대조했다. 안정된 파일 3개의 재수집에서 세션·메시지·도구 메모·검색 조각·트랜스크립트 이력 집계가 같았다. 바이트 접두사가 같고 내용이 추가된 실제 파일 3개에서 증분 수집으로 메시지 16개와 도구 메모 21개가 추가됐고 이력 3개가 갱신됐다.
- 설치 시 같은 파일 루트가 별칭 경로로도 스캔돼 이미 수집한 파일이 다시 대기열에 올랐다. 설치 시각, Codex 수집 종류, 대기 상태, 의존 작업 부재, 파일과 저장 지문의 일치를 대조한 뒤 중복 일감 2,601개를 지원되는 취소 명령으로 정리했다. 신규·변경 파일과 실행 중인 일감은 남겼다. 이후 운영 데몬이 명시 수집 없이 새 세션 8개를 자동 수집했다. doctor는 메타 오류 제외 5개, 미해결 수집 실패 0개와 마지막 수집 시각을 표시했다. 최종 DB 조회에서 대기 일감과 실패가 각각 0건이었다.

## 제품 보완과 회귀

- `f53793a5`에서 한 파일의 메타 ID를 확정할 수 없으면 그 파일만 제외하고 정상 파일을 계속 스캔하도록 수정했다. doctor에 제외 건수를 노출한다. 서로 다른 유효 파일의 동일 ID 충돌과 디렉터리 I/O 오류는 전체 오류로 유지했다. 독립 리뷰와 후속 검토를 거쳐 직접 관련 시험 137개를 검증했다.
- 최초 통합 TypeScript 실행은 278파일 5,780사례에서 5,744개 통과, 21개 실패, 15개 미완료였다. 임시 Drive 시험 환경이 실제 Codex 폴더로 넘어가는 경로를 확인해 한 시험 워커를 중단했다. `40e6d796`에서 Drive 시험 환경에 전용 Codex 경로를 지정했다. 최초 재검증에서 인라인 테스트의 경로 오류 2개도 수정했다. 최종 영향 파일 3개 74사례가 모두 통과했고, 영향 밖 275파일의 5,706개와 합쳐 5,780개를 확인했다. 전체 TypeScript 재실행은 하지 않았다.
- 순차 Python 전체 실행은 12파일·29작업·55사례 모두 통과했다. 직접 관련 파일 재검증도 공용 시험 잠금과 전용 PostgreSQL을 사용했다. 중단된 두 시험 컨테이너는 소유·종료·접속 0건을 확인해 정리하고 공식 복구로 장부의 자원 0개를 확인했다.
- 스캔에 필요한 두 루트가 확인되었다. 사용자 hook 또는 notify를 연결하는 작업은 하지 않았으며 실제 운영은 스캔으로 검증했다. 파일별 반복 목록 조회는 대량 재수집의 처리량을 낮출 수 있다. 실제 자료와 검증 로그는 로컬 `.brain-automation/tickets/23.6/`에 보관하며 공개 기록에는 집계만 남긴다.
