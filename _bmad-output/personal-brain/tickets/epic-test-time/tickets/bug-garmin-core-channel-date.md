# Garmin 회귀: 중단 복구 두 사례의 사진 전송 단언 실패

## Description

Garmin 통합 회귀의 두 중단 복구 사례가 사진 한 번 전송을 기대하지만 사진 묶음 전송을 관찰해 실패했다. slot을 사용하지 않는 같은 작업 트리의 기존 격리 경로에서도 같은 실패가 나와 Python 병렬화의 최종 회귀를 막는다. 시험 입력과 실제 전송 계약의 관계를 밝혀 실행 날짜에 흔들리지 않는 회귀를 복구한다. 기존 코드의 결함인지 시험 전제의 결함인지는 아직 확정하지 않는다.

## Reproduction

1. 19.5의 기준 cb5214293d3169977a6e006940b41da52a305dc8에 당시 미커밋 runner 변경이 있는 작업 트리에서 합성 Garmin·모델·Telegram 서버, 전용 PostgreSQL과 home으로 Python 선정 진단을 실행했다.
2. 2026-11-08 05:02:45~05:13:30 UTC의 1 slot 실행에서 16파일 중 15파일이 통과하고 Garmin core의 database·exit 중단 복구 두 사례가 실패했다.
3. 두 사례 모두 sendPhoto 1회 기대에 실제 0회, sendMediaGroup 1회였다. 05:15 UTC의 slot 미사용 기존 fixture 경로 단독 실행에서도 같은 실패가 기록됐다.
4. 기존 Git 기준만의 깨끗한 작업 트리에서 재현됐다는 증거는 아직 없다. 당시 명령·환경·원문은 아래 로컬 진단 자료로 인계한다. 현재 날짜에서의 성공만으로 과거 보고를 반증하지 않는다.

## Cause Hypothesis

시험이 실제 오늘에서 이틀 뒤의 날짜를 만들며 그래프 수에 따라 단일 사진과 사진 묶음 전송이 갈리는 경로와 충돌할 가능성이 있다. 실제 날짜, 합성 데이터의 관측 범위, 그래프 생성·선택, 채널 재시도를 대조해 판별한다. 날짜 의존성과 기존 기준 귀속은 가설이며 특정 수정법이나 전송 형태 변경을 요구하지 않는다.

## Acceptance Criteria

1. **두 중단 복구 사례의 전송 결과가 설명되고 안정적으로 검증된다**
   **Given** 보고 당시 날짜 조건과 합성 데이터, database·exit 중단 복구 사례
   **When** 격리된 기존 fixture 경로에서 수집·복구·평가·파일 등록·전송을 끝낸다
   **Then** 각 사례의 그래프 개수·종류와 실제 전송 방식이 의도한 계약에 맞으며, 메시지·사진·문서 전송 횟수와 500 뒤 재시도 결과가 정확히 검증된다. 과거 기대가 잘못됐다면 근거를 제시하고 정확한 새 기대를 독립 확인한다.
2. **달력 조건과 전송 분기의 회귀를 지킨다**
   **Given** 보고 날짜와 그래프 선택에 영향을 주는 인접 날짜 또는 기간 경계, 단일 사진과 사진 묶음 입력
   **When** 각 입력의 검증이 실행된다
   **Then** 기대 결과가 실행일과 무관하게 결정되며 각 전송 분기와 실패 후 재시도가 정확한 개수·내용으로 검증된다. 해당 분기가 기존 별도 시험에서 검증된다면 그 근거를 연결해 중복을 피한다.
3. **병렬화 없이도 수정 근거와 전체 회귀가 성립한다**
   **Given** 원본 Git 기준과 수정 결과 및 격리된 시험 자원
   **When** 개발·독립 리뷰가 끝난 뒤 필수 전체 TS → Python 회귀를 순차로 한 번씩 실행하고 필요한 관련 실패를 재검증한다
   **Then** 보고 실패의 원인과 기준 귀속의 확인 범위를 구별해 기록하고 두 사례가 통과하며, 남은 필수 실패가 없다. 19.5 runner 변경 없이 성립하는 수정·검증 결과와 정확한 source SHA를 인계한다.
4. **또는 수정 불필요를 증명한다**
   **Given** 보고 당시 날짜·데이터·환경과 두 중단 복구 사례
   **When** 원인 가설과 실제 계약을 대조하고 해당 조건을 검증한다
   **Then** 기대 동작이 이미 성립하거나 보고 전제가 잘못됐음을 근거와 함께 기록한다. 이 결과는 수정 요구를 대체하되 현재 날짜에서 우연히 통과한 결과만으로 대체하지 않는다.

## Boundaries

- 시험 생략, sendPhoto 또는 sendMediaGroup 중 아무거나 허용하는 느슨한 단언, timeout 증가, 실제 그래프·파일·전송의 mock 대체로 실패를 숨기지 않는다.
- 생산 수집·그래프·전송 계약은 유지한다. 제품 결함이 확인돼 제품 변경이 필요하면 원인과 최소 범위를 중앙에 먼저 알린다.
- 병렬 runner·slot·선정 정책·성능 임계는 19.5 소유다. 이 버그는 시험 입력·기대의 정확성과 회귀 복구를 소유한다.
- 운영 DB·계정·실제 건강값·발신은 사용하지 않는다. 소유 자원만 정확한 식별자로 정리하고 증거는 보존한다.
