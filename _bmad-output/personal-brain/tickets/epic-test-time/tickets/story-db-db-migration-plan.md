# 시험 DB 초기화

[티켓 원문](story-db-db-migration.md)과 [정제 명세](story-db-db-migration-refinement.md)의 수락 조건을 유지한다. 이 계획은 복구한 후보의 검증 결과와 차단을 기록한다. 당시 정적 검토와 이전 시도의 실패 기록은 보존한다.

## 실제 검증

- 대상은 redaction 41건, store 83건, work-store 170건, sessions-ingest 72건이었다. 합계 366건이다. 기준은 예열 1회와 유효 표본 3회에서 전부 통과했고, 실제 DB 준비·정리 합계의 중앙값은 71.802초였다. 목표는 동일 비교에서 후보 중앙값 35.901초 이하다.
- 첫 후보 예열은 장부 동시 갱신이 겹친 4건의 실패로 무효였다. 갱신이 실제 진행 중일 때만 기한을 두고 재관측하도록 변경했다. 독립 검토 후 새 회귀 2건과 기존 실패 4건의 직접 확인이 통과했다. 기존 실패 4건의 직접 시험은 URL만 주는 기존 초기화 경로였다.
- 전체 후보 재예열은 사례 본문 366건을 모두 통과했다. CLI 종료 단계에서 자식 5개의 종료 장부가 없어 실행은 종료 1이었다. 유효 후보 표본은 0개다. 별도 직접 시험 묶음에서는 367건 중 348건 통과, 16건 실패, 3건 선택 제외였다. 중앙 전체 회귀는 실행하지 않았다.
- 두 무효 후보의 준비·정리 원시 합계는 각각 953.981초와 960.037초였다. 두 번째 예열의 DB 제거 중앙값은 1,741ms, 준비 경로 획득은 2,072ms, 실제 복제 SQL은 27.3ms였다. 중첩 소유 확인·장부 기록을 상위 합계에 다시 더하지 않았다. 무효 표본은 성능 비율에 사용하지 않는다.

## 차단과 재개

독립 검토와 전용 자원 안전 경계를 유지한다. 종료 증명이 모자란 전용 컨테이너 3개와 작업 디렉터리를 보존했고 공용 잠금은 반환했다. 실제 자원 ID와 사설 장부는 로컬 `.brain-automation/tickets/19.1/current-result-archive/`와 원본 영수증에 있다. 회수에는 정확한 소유 대조와 자식의 종료 증거가 필요하다.

재개하려면 CLI의 미추적 자식이 실제 종료 장부에 연결됐음을 확인하고, 안전한 소유 확인과 회수를 유지하면서 반복 검증 비용을 줄일 설계를 입증해야 한다. 같은 366건이 절차·본문·종료까지 동등하고 유효 예열의 단계별 원시 비용이 목표에 접근할 근거가 생기면 기준과 후보를 정식 비교한다. 구현은 main에 반영하지 않았다.
