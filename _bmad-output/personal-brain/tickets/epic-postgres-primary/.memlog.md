- (requirement) E11-1 (R3): 제품 컨테이너 — setup이 <home>/postgres/compose.yaml(공식 postgres:18, named volume, 127.0.0.1 포트, restart unless-stopped, 비밀번호는 .env)을 쓰고 compose up --wait로 띄운다. compose project·볼륨·포트·LaunchAgent Label은 Brain 홈에서 함수 하나로 만들고 기본 홈이 아니면 접미사를 붙인다. 컨테이너를 지우고 다시 만들어도(볼륨 유지) 데이터가 같은 값으로 되읽힌다. 테스트 compose는 공식 postgres:18(tmpfs)이고 pgvector·vector 의존이 없다 (AD-34, C2)
- (requirement) E11-2 (R3): role·schema·마이그레이션 — setup만 마이그레이션 소유자 role과 brain_app, core schema brain을 만들고 생성한 비밀번호를 .env(0600)에 둔다. 런타임은 [store] url_env(기본 BRAIN_DATABASE_URL)의 brain_app 접속만 쓰고 database·schema·role을 만들지 않으며 없으면 DB_UNAVAILABLE. 실행기 하나가 brain.schema_migrations(owner, version, name, checksum, applied_at)에 소유자별 연속 번호로 기록하고 파일마다 자기 트랜잭션에서 advisory lock 아래 적용하며 번호 중복·누락과 적용된 파일의 checksum 변경을 거부한다. 확장 소유자의 마이그레이션 자리가 있다 (AD-10·20·30·31)
- (requirement) E11-3 (R18): baseline 0001 — SQLite 0001~0009와 같은 수준의 core 표(singleton schema_version 대신 schema_migrations, settings 추가), 멱등 UNIQUE 키, 불변·변경 규칙(plpgsql trigger, TRUNCATE 방어), 청구·due 색인, 검색 대상 다섯 열의 lower(col) pg_trgm expression GIN. DB는 값을 만들지 않는다. chunk_locator는 Core 정규형 그대로의 text이고 JSON object인지 CHECK한다 (AD-15·22·24·31, Table Contract)
- (requirement) E11-4 (R18): PostgreSQL Store — Store port 전부를 구현하고 공통 계약 suite를 PG에서 통과한다. 쓰기는 withWrite 하나, 같은 세션 수집은 세션 토큰 pg_advisory_xact_lock, 청구는 FOR UPDATE SKIP LOCKED, 연결 설정(경로별 lock_timeout·statement_timeout·application_name·UTC)은 연결 함수 한 곳. 쓴 ID·시각이 같은 값으로 되읽힌다. 계약 밖 adapter 시험: 두 프로세스 청구 중복 없음, 같은 세션 동시 수집, 직접 SQL UPDATE·DELETE 거부 (AD-7·8·22)
- (requirement) E11-5 (R18): DB에 못 쓸 때 — 연결 거부·접속 끊김과 brain schema 없음은 모든 verb에서 DB_UNAVAILABLE, 잠금 초과는 DB_LOCKED, 소유자별 버전 불일치는 SCHEMA_MISMATCH로 내려가 기존 spool 경로가 돈다. hook 경로의 연결 시도는 경로별 Core 상수의 짧은 시간 한도를 넘으면 spool로 가서 Harness를 막지 않는다. DB가 돌아오면 drain이 spool을 넣는다 (AD-7·9·20, NFR-3)
- (requirement) E11-6 (R18; spec CAP-2): 저장본 가리기 — messages.redact·files.redact가 PG에서 같은 트랜잭션 연쇄(본문 치환, redactions, 파생물 삭제, 정리 일감)를 지키고 실패하면 되돌리며 spool하지 않는다. 표시는 트랜잭션 로컬 GUC brain.redacting. 정리 일감은 트랜잭션 밖 VACUUM FULL 뒤 CHECKPOINT이고 끝날 때까지(실패·권한 부족·잠금 대기 포함) doctor가 warn. 정리 권한은 제한된 경로로만 주고 확장에는 주지 않는다 (AD-11)
- (requirement) E11-7 (R4): 사용자 설정 — brain.settings(key, value, updated_at)와 brain config get/set(CLI·SDK·명령 메타). 키는 설정 코덱이 정의하고 첫 키는 timezone(기본 Asia/Seoul, 유효한 IANA 이름). setup은 config.toml의 timezone을 기본값으로 보여 주고 DB에 쓰며, 그 뒤 config.toml의 timezone은 읽지 않고 남아 있으면 doctor warn. 확장 키 <ext>.* 자리가 있다. 기계 값은 config.toml, 비밀은 .env. 값이 재시작·컨테이너 재생성 뒤에도 남는다 (AD-18)
- (requirement) E11-8 (R3, R18): 설치·갱신·doctor·제거 — setup run과 플러그인 bootstrap 갱신 경로가 OrbStack 확인(없거나 꺼져 있으면 안내하고 멈춤) → compose → 컨테이너 → role·schema → 마이그레이션 → 나 → 시간대 → … → doctor → 완료 기록을 멱등으로 돌고 디스크의 transcript를 다시 가져온다. 옛 brain.db는 지우지 않고 더 쓰지 않는다는 한 줄을 보인다. doctor는 OrbStack·컨테이너·DB 접속·쓰기·pg_trgm·소유자별 schema 버전을 보이고 OrbStack 실패면 DB 항목을 이유와 함께 건너뛴다. 조회 명령은 컨테이너를 띄우지 않는다. setup uninstall은 컨테이너를 내리고 볼륨은 명시적 확인 없이는 남긴다 (AD-19·20·34)
- (requirement) E11-9 (R3, R18): 데몬 재연결 — DB에 닿지 않으면 데몬이 compose up -d를 backoff로 다시 부르고(drain 깨움이 backoff를 건너뛰지 않음), 다시 닿으면 schema 확인 뒤 drain이 spool을 넣는다. hook과 명령은 컨테이너를 띄우지 않는다 (AD-27·34)
- (requirement) E11-10 (R3, R18): 전환과 삭제 — 런타임(CLI·데몬·hook·bootstrap)이 PG Store만 쓰고, packages/sqlite, 런타임과 테스트의 node:sqlite import, SQLite 전용 doctor·설치 단계, second_brain의 SQLite 재export가 저장소에서 없어진다. 전환 뒤 Store 시험은 모두 PG에서 돈다 (AD-10)
- (constraint) C1 (parent): PostgreSQL 단일 주 저장소와 OrbStack Docker(영속 볼륨)는 확정, SQLite 원본+Postgres 복제 완료안은 인정하지 않는다
- (constraint) C2 (parent): 임베딩·pgvector·Drive 구현을 선행 조건으로 만들지 않는다 — 이 에픽은 pgvector를 쓰지 않는다
- (constraint) spec Constraints: hook은 Harness를 막지 않는다(async, exit 0), 원문 불변·나갈 때 가리기, Node >=24, Core·CLI는 TypeScript
- (decision) (by user) chunk_locator는 text로 저장한다. Core 정규형 바이트를 그대로 보존하고 V1에는 locator 안을 질의하는 곳이 없으며 성능 차이가 없다(2026-10-28)
- (decision) (by user) tracer는 실제 hook 명령까지 관통한다: 개발 홈에서 setup run이 제품 compose와 baseline을 올리고 hook이 부르는 brain sessions ingest가 PG에 쓴다. 수집 경로의 Store만 먼저 옮기고 명령별로 Store 타입을 좁힌다(2026-10-28)
- (decision) PO 결정(사용자가 이의 없음): 자원 이름 파생 규칙, role·비밀번호는 setup이 .env에, 시간대는 config.toml 값을 기본값으로 DB에, 전환과 SQLite 삭제는 별도 스토리, 전환 뒤 Store 시험은 PG(2026-10-26 '해당 시에만' 결정 대체), hook 연결 시간 한도 상수, 옛 brain.db는 지우지 않음, 데몬 재연결을 범위에 넣음, drive.keep_local_days 키는 epic-drive가 등록
- (event) self-validate pass 1(일관성): E11-1~10 각 줄이 확인 결과를 갖고 parent R3·R4·R18과 spine AD를 가리킨다. 번호 재사용 없음. chunk_locator Open question은 사용자 결정으로 닫혔다
- (event) self-validate pass 2(보존): 에픽 Description·Done when의 범위(compose, baseline, 실행기, Store, 설정, 설치·doctor, 전환·삭제, 배포)가 모두 E11 줄에 있다. 코드 조사의 추가 범위(저장본 가리기 정리 권한, 데몬 재연결, 오류 분류)를 E11-5·6·9로 더했다. 배포는 Done when 6에 남는다
