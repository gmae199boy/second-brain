### 순서·선행·충돌 대조

- 초안에 있는 모든 `after` ID는 실재한다. 내부 참조는 표에서 앞선 항목만 가리켜 내부 순환과 표 순서 역전은 없다. `2.N` 참조는 완료된 에픽 2의 `tickets.toml`, `10.N`은 에픽 10의 계획 항목으로 대조했다. 단순 ID/경로 읽기 점검이며 제품 테스트가 아니다. 초안이므로 `tickets.py status`를 실행해 공식 tickets.toml이 검증됐다고 주장하지 않는다.
- 4 → 10.2, 5 → 10.6, 6 → 10.1은 이미 선언됐다(초안 46·58·70행). 10.6 → 10.2 → 10.1 경로도 있다(10 초안 22·34행). 에픽 91행의 병렬 결정과 맞는다.
- 2·4: 의존 경로는 없지만 2는 guide 전문/규율 상수, 4는 context·명령 메타/guide schema다. 현재 서술에서 같은 함수 변경은 확인되지 않는다. 4 tracer가 아직 안내 요약을 넣지 않는 것은 명시된 부분 구현이며 요약은 9가 2를 기다려 붙인다. 선행을 기계적으로 추가하지 않는다.
- 3·4: 3은 제품 코드를 남기지 않는 사람 실측, 4는 제품 hook/코드다. 실측용 플러그인은 분리된 임시 설치에서 운용해야 하나 현재 직접 코드 충돌은 확인되지 않는다. parser 계약의 후속 영향만 지적 6에 남겼다.
- 5·6: 의존 경로는 없지만 5는 스키마/ContextInjection 타입, 6은 append·로그 spool이다. 6은 5의 새 주입 칸을 소비하지 않으므로 `after = [5]`를 반드시 넣을 근거는 없다. 5의 불변 trigger 아래 최종 회귀는 7 이후와 13에서 가능하다. 0009를 뒤늦게 바꾸라는 진짜 문제는 지적 1이다.
- 9·8: 의존 경로가 없고 같은 로그 읽기/유효성 계약의 소유가 불명확하므로 지적 4에 남겼다.
- 10·11: doctor 집계/검사와 스킬 생성은 직접 구현 표면이 다르다. 11이 기존 doctor 명령 메타를 소비한다는 이유만으로 새 doctor 검사 완료를 기다릴 필요는 없다. 현재 코드 충돌을 입증하지 못해 선행을 요구하지 않는다.
- 에픽 10의 handler 맵·Store 합성·spool 종류·CLI registry·doctor 목록·codes.ts는 승인된 병합 범위로 처리했다. I94/I105의 연기를 뒤집지 않았고, 없는 MCP 구현을 이 에픽의 추가 일감으로 만들지 않았다(에픽 89·91행, 코드 조사 §10).

### 그 밖의 확인

- 3은 실측 숫자와 최종 결정을 에픽 Notes의 `Decision:`으로 남기고 12에 넘기므로 단순 조사 종료가 아닌 결정 산출물 형태다(초안 31~34행). 다만 지적 6의 최종 parser 계약이 필요하다.
- 첫 항목이 tracer가 아닌 이유와 선행 준비 1~3의 취지는 에픽 91행에 명시돼 있다. 이 승인된 예외를 재지적하지 않았다. 13 Refactor sweep는 마지막이며 다른 12개 전부를 기다린다(초안 145~153행). 근거는 기준 Set 18·20행이다.
- 초안의 명시적 references 경로는 모두 존재하고 텍스트로 열렸다. 에픽·두 조사·에픽 2/10 분해 파일도 열었다. 빈 assignee 등 에픽 메타는 실행용 leaf 기준 누락으로 취급하지 않았다.
- “최소”, “나중에”를 근거 없이 요구사항 축소에 쓰는 문장은 초안에서 확인하지 못했다. 4의 얇은 경로는 6~9로 확장되고, 미구현 에픽 4 명령의 스킬 제외·Postgres의 에픽 7 이관·I94/I105 연기는 이미 명시된 경계/결정이다. 빌드 계획에서 정할 질문 자체를 결함으로 삼지 않고, 여러 소비자보다 늦게 정하는 계약과 실행 불명확한 verify만 지적했다.
- 검증 과정에서 기존 작업 트리에 에픽 수정과 조사/초안 파일이 있었으며 그대로 두었다. 이 작업이 만든 파일은 이 보고서 하나다.
