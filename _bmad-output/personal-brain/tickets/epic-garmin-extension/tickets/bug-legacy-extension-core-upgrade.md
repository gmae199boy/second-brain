# 등록 확장이 있는 옛 core 설치본이 안전한 오프라인 갱신 경로 없이 막힌다

## Description

옛 core schema27에 비활성 확장이 등록되어 있으면 새 설치기는 확장 정지 표가 없다는 이유로 무조건 거부한다. 안내대로 이전 실행을 종료하고 오프라인 확인을 준비해도 확인 단계에 도달하지 못한다. 같은 DB와 기존 기억을 유지하면서 안전 전제를 충족한 옛 설치본이 새 설치본으로 이행할 수 있어야 한다. 실제 이 Mac 전환은 21.7이 수행하며 이 버그는 제품 경로와 합성 검증만 다룬다.

## Reproduction

1. 격리 home과 소유 전용 PG에 core schema27, 등록된 비활성 확장, 보류 예약을 가진 합성 옛 설치본을 준비한다. 공용 대화·파일·채널·설정 및 사용자 상태의 보존 기준을 만든다.
2. 새 실행을 차단하고 진행 중 작업·attempt가 없고 이전 데몬·직접 확장 명령·쓰기 자식이 종료된 조건에서 지원 설치 진입점으로 새 core 갱신을 요청한다.
3. 현재 결과는 `DB_LOCKED: 기존 확장의 실행을 안전하게 정지할 수 없는 옛 schema`다. 오프라인 확인 단계보다 먼저 거부되며 활성 app은 유지된다. 옛 CLI에는 ext uninstall이 없고 registry 삭제·새 빈 DB는 지원 이행이 아니다.
4. 기대 결과는 아래 안전 전제를 충족하면 지원 경로로 갱신할 수 있고, 전제가 충족되지 않거나 불명이면 관련 상태 변경 전에 거부하는 것이다.

운영 관찰은 21.7의 읽기 전용 진단으로 확인했다. 이 재현은 운영 DB에서 반복하지 않는다.

## Cause Hypothesis

설치 진입점이 확장 정지 표와 설치 기록의 새 schema 신원을 전제하지만, 그 전제에 못 미치는 기존 등록 확장의 이행 경계를 제공하지 않는 것으로 보인다. 새 schema의 일반 정지 경로와 옛 실행기를 차단하는 경계 사이가 연결되지 않는다. 구체적인 전환 설계는 구현자가 기존 마이그레이션 순서·소유권·복구 계약을 조사해 정한다.

## Acceptance Criteria

1. **안전 전제를 충족한 옛 설치본의 지원 갱신**
   **Given** 위 합성 설치본에서 모든 등록 확장은 비활성, 예약은 보류, 진행 중 work/attempt는 0이고, 새 진입이 차단되어 이전 데몬·직접 명령·공유 상태 쓰기 자식의 종료가 확인됐으며 운영자가 해당 전환을 명시 확인한 상태다.
   **When** 사용자가 지원된 대화형 설치 경로로 새 core 갱신을 요청한다.
   **Then** 같은 DB와 설치 이력을 유지한 채 새 정지 계약의 일반 경로로 이어지고, core 신원·확장 호환 재확인 및 기존 migration/self/backfill 순서를 지켜 완료한다. 확장 활성화·예약 재개·실제 수집은 자동 수행하지 않는다.
2. **불명 또는 전제 미충족은 변경 전 거부**
   **Given** 활성 확장·미보류 예약·열린 work/attempt·살아 있거나 불명인 이전 실행·타 소유자 잠금/전환 journal·신원 또는 호환 불명·잘못되거나 재사용된 오프라인 확인 중 하나라도 존재한다.
   **When** 같은 갱신을 요청한다.
   **Then** 관련 DB migration·활성 app/registry 전환 전에 구체적 진단과 복구 안내로 거부하고 기존 상태를 보존한다. 단순 PID 부재나 work0만으로 미추적 자식 부재를 추정하지 않는다.
3. **오프라인 확인의 기존 의미 유지**
   **Given** 새 진입 차단 아래 해당 home·이전/목표 core 신원·시도 nonce에 결합된 운영자 확인이 필요하다.
   **When** 자동 hook·JSON·비대화형·yes 또는 다른 전환/이전 시도의 확인으로 대체하려 한다.
   **Then** 거부한다. 운영자 확인과 기계가 확인한 사실을 구별하며 진입 재개나 전제 변경 뒤에는 확인을 재사용하지 않는다.
4. **중단·실패·재시도 보존**
   **Given** 갱신 준비·migration·새 정지 지원 진입·app 승격 경계에서 실패 또는 프로세스 중단이 발생한다.
   **When** 재시도하거나 복구 안내를 따른다.
   **Then** 확정된 migration을 되돌렸다고 주장하지 않고, 기존 활성 상태 또는 명시적 소유 복구 상태를 보존한다. 새·옛 writer를 동시에 허용하지 않으며 타 소유자 정지나 사용자 보류를 해제하지 않는다. 불명 상태는 자동 회수하지 않는다.
5. **기억과 설치 상태의 보존 및 일반 경로 회귀**
   **Given** 합성 공용 대화·파일·채널·설정·사용자 데이터, 등록 확장 및 기존 사용자 예약 변경·삭제 표식·회계가 있다.
   **When** 정상 이행과 주입 실패 후 복구를 수행한다.
   **Then** 기존 forward migration이 명시적으로 허용한 정리 외 기억·상태가 보존되고, 원래 지원하는 새 설치·새 schema 일반 갱신·공통 설치 잠금 및 패키지 경로도 유지된다.
6. **제품 경로와 시험의 실제 검증**
   **Given** 소유 전용 PG·격리 home·합성 확장/설치본과 fake 외부 경계다.
   **When** 재현과 정상·거부·경합·중단 복구 시험, 독립 리뷰 및 필요한 후속 리뷰를 수행한다.
   **Then** 결함을 검출하는 회귀와 영향 경계가 실행 증거로 확인되며, 최종 `pnpm test` 다음 `pnpm test:python`이 순차 성공하고 미해결 실패가 없다. 이 티켓은 20.1~20.5·21.2~21.6 시험 실행 유예 대상이 아니다.
7. **또는 이미 지원됨을 입증**
   **Given** 현재 코드에 위 정상 및 거부 기준을 충족하는 경로가 있다고 판단한다.
   **When** 같은 합성 재현에서 외부 설치 진입점으로 실행한다.
   **Then** 그 지원 절차와 보존·거부 증거를 기록한다. 코드 변경이 필요 없다는 입증은 1~6의 기능 변경을 대체할 수 있으나 운영 진단만으로 완료하지 않는다.

## Boundaries

기존 A1 불명 잠금 보존, 오프라인 확인, 사용자 보류·타 owner 보호와 공통 기억 계약을 유지한다. registry SQL 삭제·DB 교체·guard 단순 삭제·새 OS 감독/강제종료 정책·적용된 migration 수정은 제외한다. core에 특정 확장 이름·표·지표·프롬프트를 추가하지 않는다. 합성 구버전 확장을 사용하며 실제 운영 이행·계정 확인·옛 예약 변경은 21.7에 남긴다. 새 uninstall 제품 기능은 요구하지 않는다.
