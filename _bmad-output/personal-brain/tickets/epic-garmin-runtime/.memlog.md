- (requirement) E16-1 (R2, R11; C4): connector 편입 — 옛 Python 코드(소스 `7fb33dd`)를 epic 14의 확장 뼈대에 편입한다. SQLite store는 garmin schema의 PG store port로, deploy·Garmin LaunchAgent는 core 설치·공통 예약으로, Telegram 직접 발신은 채널 발신 요청으로, config TOML은 설정 snapshot으로 바뀐다. 옛 의존(garminconnect·curl-cffi·jsonschema·matplotlib·requests)을 epic 14의 lock(pin 3.14.10 + `psycopg[binary]`)에 더해 다시 잠그고, macOS arm64에서 frozen 설치·import가 검증된다. 수집 경로는 모델을 부르지 않는다. (AD-29·33, spine Deferred "Garmin lock·설치 재현성"의 epic 16 몫)
- (requirement) E16-2 (R11): 인증과 계정 보호 — 세션은 라이브러리의 login/dump로 tokenstore(`garmin.tokenstore`, 기본 `~/.garmin-pipeline/tokens`, 폴더 0700·파일 0600)에서 연다. 비밀번호·MFA를 받는 대화형 로그인은 epic 13의 인증 단계로만 하고, 감독자 일감의 JSONL stdout과 섞지 않는다. 호출 간격(호출마다 1~2초, 날짜 사이 5초), 연속 403 세 번이면 차단, first-call 보호(실행당 endpoint마다 3건)를 지킨다. 429·403 차단과 인증 실패·MFA 필요는 외부 호출 전에 garmin schema의 계정 보호 상태로 먼저 저장한다. 인증 실패·MFA 필요는 재인증이 성공할 때까지, 429·403 차단은 다음 현지 날짜에 탐색 호출 하나가 성공할 때까지 예약·수동·force 실행 모두 외부 호출을 하지 않는다. 다음 날에도 다시 차단되면 수동 해제(`brain ext run garmin release-block`)가 있어야 풀리고, doctor가 보인다. 인증·수집은 epic 12의 `(source, account)` 직렬화 키를 쓴다. 비밀은 argv·로그·stdout·오류 문장에 나오지 않고, 오류는 허용 목록의 코드·단계·endpoint만 낸다. (AD-18·33)
- (requirement) E16-3 (R2, R11): 수집과 coverage — 날짜 endpoint 11개와 활동 endpoint 4개, history_start(이전된 운영 dataset의 값이 있으면 그것, 없으면 첫 실행 today−30), 실행당 최대 10일, 11:15 재시도 진입표, recent_lists, 거부 일수 상한을 옛 의미대로 지킨다. raw는 라이브러리가 decode한 객체를 `json.dumps(ensure_ascii=False)`한 그 문자열이고, NoData·checked_at·fetched_at·library_version 전이도 옛 의미다. 새 raw는 garmin 보존 표에 새 수집 dataset으로 이어 쓰고 이전된 행을 덮지 않는다. coverage는 같은 계정의 모든 dataset(이전된 raw 포함)을 본다. 14.8 capture 뒤의 날짜는 다시 반입하지 않고 새 수집이 받는다. (AD-30·32)
- (requirement) E16-4 (R2, R11; AD-32): 정규화와 건강 계약 — 정규화 버전 8의 순수 계산을 재사용하고, 결과는 14.2의 보관 키로 새 행만 INSERT한다(DELETE·UPDATE 없음). 같은 raw를 다시 처리하면 멱등이고, 바뀐 raw는 새 관측 revision 행이며, rebuild는 새 정규화 버전 행이다. 항목별 실패는 격리돼 normalize 상태에 남는다. 권위 기록에 새 수집 dataset을 맨 앞에 둔 새 규칙 버전(v2: 새 수집 → D2 → D1 → D4 → D5 → D3)을 쓰고, 규칙 v1은 바꾸지 않는다. 계정 identity는 로그인 profile의 Garmin 사용자 profile id다. 같은 합성 fixture에서 raw·정규화 결과가 옛 구현과 같다. (AD-32)
- (requirement) E16-5 (R2, R11): body·digest — body는 원본 참조와 검증 JSON으로 필드별 mtime 병합을 지키고(NaN·Infinity·중복 key 거부), 원본 파일은 옮기기 전에 `file_requests`로 보낸다. digest는 순수 계산이고 모델 서술과 분리된다. digest의 일 값(day values)은 core 건강 요약 행이 되며, catalog에 없는 지표는 호환 core 마이그레이션으로 catalog에 더한다. 같은 합성 fixture에서 digest·weight-lifestyle 결과가 옛 구현과 같다.
- (requirement) E16-6 (R2): 그래프 — 그래프 PNG(Agg, 12×6 inch·150 DPI, Apple SD Gothic Neo → DejaVu Sans, private MPLCONFIGDIR, 파일 0600, 10,000,000 bytes 상한, 그래프별 실패 격리)를 만들고 `file_requests`로 보낸다. 요청에는 현지 날짜·그래프 이름·산출 revision이 있어 epic 18의 결과 묶음이 고를 수 있다. 성공 PNG 바이트는 core 확인까지 보존한다. 한국어 종목 이름 리소스는 확장 패키지로 옮기고 normalize·digest·그래프가 같은 loader를 쓴다.
- (requirement) E16-7 (R11; R13은 epic 15 경유): 수집 사건 알림 — auth_failed·rate_limited·blocked_403·normalize_failed·repeated_partial·error 여섯 사건을 채널 발신 요청으로 낸다. 의미 키는 `(생산 결과 식별자 = (source, account, timezone, 현지 날짜, 사건)의 안정 사건 행 id, conversation = Garmin 봇·채팅, 목적 = collection-notice:<사건>, 개정 = 사건 템플릿 revision)`이다. 같은 날 같은 사건은 처음 사건 행을 다시 쓴다. 사건 행과 요청은 짧은 트랜잭션 하나에 넣는다. 실제 재시도는 epic 15의 결정을 따르고, 확장은 Telegram을 직접 부르거나 봇 설정을 읽지 않는다. (AD-30·35)
- (requirement) E16-8 (R2, R10): 일감·예약·manifest — manifest가 `collect`(받은 항목의 증분 정규화와 publish까지), `normalize`(rebuild·미발행 raw 재개), `artifacts`(body·digest·그래프, collect 뒤 의존), `release-block`(수동), 연결 확인을 선언한다. 기본 예약은 collect 11:00·retry 11:15이고 시간대는 core 설정이다. `garmin.*` 설정 키는 옛 `_DEFAULTS`에서 온다(분석 키는 epic 18). 수동 실행은 `brain ext run garmin <job>`이다. 진행 이벤트를 endpoint·날짜·batch마다 내고 그 경계에서 취소에 반응한다. 옛 `_abandon_running`은 감독자가 대신한다. 결과(성공·부분·차단·인증 필요)는 ABI 결과로 명시하고, 종료 코드 0을 성공으로 뭉뚱그리지 않는다. 확장을 끄면 12.10의 보류 그룹이 예약과 청구를 막는다. (AD-33)
- (requirement) E16-9 (R2; Done when 4·5): 전환과 이 Mac — 플러그인 배포 뒤 설치본에서 공통 예약을 등록하기 전에 옛 `local.garmin-pipeline.collect` LaunchAgent를 내린다(plist는 복구용으로 남김). 옛 report LaunchAgent는 그것이 스스로 수집을 부를 때만 함께 내리고, 아니면 epic 18의 전환까지 둔다. 옛 수집과 새 수집이 같은 계정을 동시에 부르는 때가 없다. 에이전트가 옛 tokenstore로 실수집 한 번을 돌린다.
