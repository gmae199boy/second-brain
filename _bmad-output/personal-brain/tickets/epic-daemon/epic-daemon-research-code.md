# daemon 에픽 코드 조사

읽기 전용 조사. `.codegraph/`가 없어 `rg`와 소스 열람을 사용했다. 빌드·테스트는 실행하지 않았다. 아래 경로는 저장소 기준이다.

1. **CLI 트리·메타.** `apps/cli/src/commands/index.ts:31`의 `commands`가 단일 레지스트리다. `dispatch.ts:227`의 필수 메타는 usedFor/required/examples/output/risk/hook/dryRun이며, `:258`의 CommandSpec에 ns/verb/options 등을 선언한다. `:887`에서 Commander namespace와 verb를 자동 생성한다. daemon run/start/stop 각각의 spec을 추가하면 help와 `brain guide schema`에 함께 노출된다(`commands/guide-schema.ts:47`). 장기 실행·프로세스 제어에는 standalone 여부와 런타임 의존성 전달을 설계해야 한다. 일반 DB 명령은 완료 후 Brain을 닫는다(`dispatch.ts:659`).

2. **Core·scan·drain.** `packages/core/src/brain.ts:224`: `createBrain(dependencies: BrainDependencies): Brain`; 의존성은 `:55`(store/files/spool/clock/idGen/parsers/transcripts/repositories/machine 등). `brain.queue.drain({budgetMs, handlers?})`는 `:142`, `:186`; 별도 `brain.scan`은 없고 공개 함수 `scanTranscripts(dependencies, {deadline}): Promise<ScanTranscriptsReport>`가 `capture/scan.ts:128`, 재수출은 `index.ts:106`이다. drain은 spool replay→scan→identity 후보→파일 이름 보충→재추출 enqueue→queue를 같은 deadline으로 수행한다(`brain.ts:431`). 예산은 명시 drain 30초·opportunistic 2초이며 처리 중 항목을 중단하지 않는다(`domain/work-item.ts:135`). 성공한 일반 DB 명령 뒤 별도 짧은 busy-timeout 연결로 opportunistic drain; hook/실패/명시 drain은 제외한다(`dispatch.ts:646`, `:685`, `:729`). SessionStart는 async bootstrap 다음 `queue drain`을 실행한다(`plugin/hooks/hooks.json:3`, `plugin/bin/session-start.sh:158`). Stop/SessionEnd는 ingest다.

3. **install lock.** 실제 구현은 `tooling/bootstrap/src/bootstrap.ts:1000`의 비공개 takeLock: `<home>/install.lock/`를 atomic mkdir하고 `pid`에 십진 PID 기록, finally에서 해제한다. PID 사망 **또는** 디렉터리 mtime 30분 초과면 한 번 회수한다(`:115`, `:1017`); kill(pid,0)의 EPERM은 생존으로 본다(`:1252`). shim은 같은 폴더를 mkdir하지만 stale 회수는 없다(`apps/cli/src/install/shim.ts:177`). daemon.pid 파일에 바로 재사용할 API는 없다. 특히 생존 PID도 30분 후 stale인 설치 규칙을 장기 daemon에 그대로 복사하면 중복 실행될 수 있으므로 잠금 형태·갱신·회수 규칙을 명시해야 한다.

4. **setup.** `apps/cli/src/commands/setup-run.ts:48`→`install.ts:98`→`install/flow.ts:333`이 공통 설치 흐름이다. 별도 step 레지스트리 없이 절차 코드: 설정/경로·동의→충돌 확인→마이그레이션(`:476`)→self→files 준비→설정 쓰기→shim→connector→doctor(`:552`)→shim 검증→installed.json(`:591`). plugin bootstrap도 `dist/install.js`를 호출한다(`tooling/bootstrap/src/bootstrap.ts:433`, `:463`). upgrade/uninstall은 레지스트리에 없으며, 실행 가능한 launchd/LaunchAgent/plist/launchctl 구현도 없다. queue-drain 주석의 “launchd 5분”은 구현 증거가 아니다.

5. **doctor.** `apps/cli/src/doctor/checks.ts:118`의 runtimeChecks 목록(`:130`)에 `{id, run}`을 추가하면 CLI와 설치 후 점검에 모두 들어간다. Core는 추가 sources를 순차 실행한다(`packages/core/src/doctor/doctor.ts:173`). 상태는 ok/warn/fail/skip이고 fail만 exit 1이다(`:25`). PID·heartbeat·LaunchAgent 같은 머신 점검은 이 런타임 목록이 적합하다.

6. **home·디렉터리·로그.** `apps/cli/src/config/paths.ts:78`: 비어 있지 않은 SECOND_BRAIN_HOME, 아니면 `~/.second_brain`. run/log 상수는 `:47`, `:68`; run에는 plugin.json·last-hook 기록이 있다(`:99`, `:125`). bootstrap은 log/bootstrap.log에 append하며 시간 헤더를 쓴다(`tooling/bootstrap/src/bootstrap.ts:1141`). 회전 helper, daemon.log, heartbeat 작성기는 없다.

7. **spool.** 포트 `packages/core/src/ports/spool.ts:17`는 append 한 번당 새 완결 파일을 보장한다. `apps/cli/src/runtime/spool.ts:106`의 `fileSpool({folder,clock,pid?,isAlive?})`, `append(records)`는 시간-PID-serial 이름으로 `.jsonl.open`을 writeFile한 뒤 `.jsonl`로 rename한다(`:130`). 따라서 resident 프로세스도 호출마다 segment가 닫혀 process exit를 기다리지 않는다. 버전 1 JSONL, 줄당 64KiB; schema_version/id/kind/occurred_at/payload를 기록한다(`packages/core/src/domain/spool-record.ts:31`, `:253`). 지원 kind는 session_ingest/failure/attachment_link(`:78`); 임의 scheduled-work enqueue를 보존하는 범용 spool kind는 없다.

8. **work_items.** 생성은 `packages/sqlite/migrations/0002_files_and_work.sql:40`; due는 run_after가 아니라 next_attempt_at이다. kind/target_kind/target_id, attempts, claim 세 필드, last_error/completed_at을 가진다. 미완료 target별 unique는 `:78`, due 인덱스 변경은 `0004_capture_columns.sql:409`. 실제 handler 레지스트리는 `packages/core/src/brain.ts:261`: session_identity/session_ingest/document_extract/blob_delete, 외부 workHandlers 병합(`:277`). source_sync는 없다. claim은 미완료·due·lease 만료·지원 kind만 attempts/id 순서로 선택한다(`packages/sqlite/src/work.ts:76`). BEGIN IMMEDIATE에서 attempts 증가·10분 lease 설정(`:202`), 종료 갱신은 claimed_by CAS(`:136`); 최대 10회(`packages/core/src/domain/work-item.ts:59`).

9. **감시·폴더 발견.** 파일 watcher는 없다. `apps/cli/src/harnesses.ts:47`→Claude TranscriptFolder; CLAUDE_CONFIG_DIR 또는 `~/.claude/projects`의 프로젝트별 직계 jsonl을 나열하며 subagents/tool-results는 제외한다(`packages/claude-code/src/transcript-folder.ts:14`, `:59`). scan은 경로·size 변화와 parser 버전을 비교하고 미완료/실패 항목 중복을 피한다(`packages/core/src/capture/scan.ts:42`, `:128`). Brain 파일 루트는 config.filesPath를 사용하는 localFileStore다(`apps/cli/src/dispatch.ts:572`).

10. **테스트.** CLI 통합은 `apps/cli/test/`, Core는 `packages/core/test/`, SQLite 실제 DB·다중 프로세스는 `packages/sqlite/test/`. `apps/cli/test/queue-drain.test.ts:25`, `:76`은 process.execPath로 dist/bin.js를 spawn하고 임시 SECOND_BRAIN_HOME·stdout/stderr/exit를 검사한다. `test/temp-home.ts:6`은 OS tmp 생성·정리, `test/environment.ts`는 harness 환경 격리를 제공한다. fake 시간은 `packages/core/src/testing/fakes/clock.ts:4` fixedClock와 `:13` steppingClock. 기존 통합 테스트는 사전 빌드가 필요하다.

11. **부분 구현·충돌.** daemon 관련 실물은 run/log 경로, drain·scan, SessionStart 호출이며 pid/heartbeat/SIGTERM/상주 루프는 없다. `packages/core/src/codes.ts:72`, `:308`에는 미래 daemon 경고/handshake 코드만 있다. 첨부 에픽10과는 Core assembly/handler·spool(`brain.ts:261`, `:296`), 파일 재추출·삭제 및 scan/drain(`:470`)이 겹친다. 운영 에픽5와는 setup 흐름·마이그레이션·doctor·완료 기록 순서가 겹친다. 계획의 최신 V1 수정은 과거 주기 LaunchAgent를 폐기하고 daemon Label을 에픽9에 배정했다(`_bmad-output/personal-brain/tickets/epic-operations/epic-operations.md:17`); `:21`의 옛 두 Label 설계는 그대로 구현하면 안 된다. uninstall의 daemon 제거 책임도 `:38`에서 에픽9로 넘긴다.
