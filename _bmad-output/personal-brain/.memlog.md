- (event) update 시작(2026-10-28): 입력 prep-garmin-absorption/accepted-intent.md(S1~S14·E1~E6)와 그 initiative 초안(R1~R17·C1~C5). 기존 spec-brain-v1-slice-1의 CAP-1~14는 그대로 둔다. 초안의 R·C 번호를 지킨다
- (decision by user) 준비 패키지를 personal-brain에 채택한다. 공통 기반·Garmin 흡수는 이 이니셔티브의 에픽으로 둔다(별도 이니셔티브 아님)
- (decision by user) 순서: PostgreSQL 전환 → 공통 기반·Garmin → Drive → V1 뒤 에픽. Drive는 Garmin의 선행 조건이 아니다(C2)
- (decision by user) epic 7(복제)을 drop한다: SQLite 원본·Postgres 복제 모델이 없어졌다
- (decision by user) 기존 brain.db는 옮기지 않는다(운영 전). PostgreSQL을 빈 DB로 설치하고 디스크의 transcript를 다시 가져온다. transcript로 되살릴 수 없는 첨부 원본은 잃을 수 있다. 전환 뒤 SQLite adapter와 node:sqlite 경로를 지운다. move-store는 필요 없다. Garmin 데이터·분석은 옮기고 보존한다
- (decision by user) spec 제약 'Brain은 LLM을 부르지 않는다'와 Done when 5·Success signal의 LLM 호출 0을 없앤다: 공통 스케줄러가 모델을 부르는 작업을 돌린다
- (decision by user) Core·CLI·플러그인은 TypeScript, Garmin 확장은 기존 Python을 프로세스 경계 너머에서 재사용한다. spec의 '구현 언어는 TypeScript'를 고친다
- (decision by user) 공통 텍스트 검색·원문 읽기는 새 에픽이 만들고 대화 검색(CAP-6·7의 대화 조각·도구 메모·넓히기)을 epic 4에서 가져온다. Drive E8-6은 같은 경로에 문서 대상을 더한다
- (decision by user) 공통 채널 계약과 Telegram 발신은 별도 에픽으로 Garmin 런타임 앞에 둔다
- (decision) 사용자 설정 DB와 brain config(epic-drive E8-7)를 PostgreSQL 전환 에픽으로 옮긴다: 확장 설정(R4)과 같은 계약이고 Drive가 Garmin 뒤로 갔다
- (requirement) R1 (S1): Garmin 미설치 Brain의 기본 설치·데몬·대화 수집이 동작하고 Garmin Python 의존성을 요구하지 않는다
- (requirement) R2 (S1, S11): Garmin 확장을 설치·활성화한 사용자가 별도 Garmin 제품 설치·예약 없이 연결·수집·분석한다
- (requirement) R3 (S2, E1, E5): 대화·파일 메타데이터·설정·작업·건강 데이터의 주 저장소는 OrbStack Docker의 단일 PostgreSQL이고, 컨테이너 재생성 뒤 보존이 검증된다
- (requirement) R4 (S4): 사용자·확장 설정은 DB에서 읽고 갱신하며 재시작 뒤 유지된다. 기계별 bootstrap은 config.toml, 비밀은 .env(기존 계약)
- (requirement) R5 (S3, S12, E2): 실제 존재하는 모든 Garmin 이전 대상의 원본·수치·기존 분석/파일을 출처 목록으로 관리하고 이전 뒤 값·본문·파일 해시·관계 동등성을 검증한다
- (requirement) R6 (S3, E2, E3): schema10/15 등 기존 Garmin 소스를 먼저 원형 보관하고, legacy 데이터와 서로 다른 후보의 충돌을 자동 폐기하지 않는다
- (requirement) R7 (S3, S12): 같은 이전 batch 재실행이 중복을 만들지 않고, 실패 뒤 재개되며, 기존 원본·AI 분석을 덮어쓰거나 재분석으로 대체하지 않는다
- (requirement) R8 (S5): 독립 작업(대화·문서 수집, 건강 분석)이 병렬로 돌고, 평가 입력 의존성과 같은 계정 수집의 직렬성이 유지된다
- (requirement) R9 (S6): 긴 작업의 소유권이 유지되고 작업자 사망·오류·정체·사용자 취소가 구분되어 복구 또는 종료된다. 임대 시간 경과만으로 정상 작업을 중복 실행하지 않는다
- (requirement) R10 (S5, S11, S14): 현지 일자·시간대 예약과 수동 실행이 같은 작업 계약을 쓰고 같은 대상 중복을 막는다. 모델을 부르는 분석 작업도 같은 계약으로 예약된다. 자동 예약은 공통 스케줄러가 선행 조건이고 미준비를 설정 완료로 표시하지 않는다
- (requirement) R11 (S11, E1): 기존 수집의 token/session/MFA·계정 차단·호출 간격과 raw/정규화/수치/입력 필터 계약을 fixture와 실패 경계 검증으로 보존한다
- (requirement) R12 (S11, S12): day→7d→30d→all 평가 순서와 성공 결과의 개별 보존을 유지하고, 계산·평가 성공과 채널 전송 성공을 따로 기록한다
- (requirement) R13 (S7): 초기 Garmin 발신은 공통 채널 계약을 쓰고, 이후 사용자 답변·스레드·에이전트 선제 메시지를 같은 대화에 잇는 identity·provenance 경계를 제공한다
- (requirement) R14 (S8, S9): 에이전트가 텍스트 검색과 원문 조회로 대화·리포트·분석을 날짜·출처와 함께 찾고 근거를 읽는다. 한국어 두 글자·표현 바꾸기 회귀 문항 포함
- (requirement) R15 (S9): 건강 수치를 기간·지표·운동·집계 조건으로 조회하고 합계·평균과 단위·NULL·현지 날짜 규칙을 코드에서 검증한다
- (requirement) R16 (S1, S3, S12): 확장을 비활성화해도 기존 건강 기억·분석이 보존되고 검색 가능 여부·작업 중단 상태가 드러난다
- (requirement) R17 (S13, S14): 플러그인에 기본 포함한 공통 install 스킬을 Garmin 미설치 상태에서도 쓰고, 에이전트가 Brain CLI로 상태를 확인해 설치·로그인·공통 예약을 안내한다. 재실행·실패·스케줄러 미준비를 구분하고 성공한 단계만 완료로 보고한다
- (requirement) R18 (S2; spec CAP-1, CAP-2, CAP-11, CAP-14): Garmin 없는 Brain의 기존 기능(hook 수집, 데몬·drain·spool, 첨부·문서 추출, 비밀 가리기, doctor)이 PostgreSQL에서 같은 계약을 지킨다: Store 공통 계약 테스트, 같은 배치 두 번 = 같은 건수, 원문 불변, 나갈 때 가리기. DB가 꺼져도 hook은 Harness를 막지 않고 spool에 남긴다
- (constraint) C1 (S2): PostgreSQL 단일 주 저장소와 OrbStack Docker(영속 볼륨)는 확정. SQLite 원본+Postgres 복제 완료안은 인정하지 않는다
- (constraint) C2 (S8): 임베딩·pgvector·Drive 구현을 Garmin 흡수의 선행 조건으로 만들지 않는다
- (event) C3(준비 문서 전용: 이번 작업에서 반입·발신·배포 안 함)은 준비 단계에만 해당해 옮기지 않는다
- (constraint) C4 (S11): Python 전면 재작성은 필수 아님. Core·CLI·플러그인은 TypeScript, Garmin 확장은 재사용 가능한 Python 계산·인증·호출 보호·테스트를 프로세스 경계 너머에서 쓴다
- (constraint) C5 (S12, E2): 기존 분석의 모델·생성 시각이 없으면 원문과 알려진 출처를 보존하고 빠진 metadata를 명시한다. 추정값을 실제 기록처럼 만들지 않는다
- (constraint) C6 (S3, E3): Garmin 데이터 실제 반입은 사용자가 기준 소스와 겹치는 자연키의 충돌 처리를 정한 뒤에만 한다. 그 전에는 모든 후보를 별도 출처로 보존한다
