## 한 줄 판정

CAP 13개는 모두 주인이 있고 공유 CAP의 분담도 적혀 있으며 의존 그래프에 순환이 없다. 그러나 **에픽 파일의 `after`가 전부 비어 있어 보드가 순서를 모르고**, 소유자 없는 spine 조각(workspaces·`sessions failures/retry`·`admin reindex`·doctor 항목·`UNINDEXED`/`CURSOR_RESET`·SM-7)이 남아 있고, Done when 두 곳이 자기 경계 밖(미러, 원문 읽기)을 확인하려 한다. 아래 fix를 처리하면 인셉션으로 넘어갈 수 있다.

## 상태 점검 결과

```
uv run .../bmad-ticket/scripts/tickets.py --project-root <repo> \
  status <repo>/_bmad-output/personal-brain
→ {"folder":"personal-brain","store":"repo","tickets":[],"counts":{"total":0},
   "longest_remaining_chain":[],"unpinned_after":[],
   "epics":[{slug:epic-foundation-and-install,id:1,status:"",after:[],blocks:[]}, … id 6까지 모두 after:[] blocks:[]]}
```

- 이상한 점: **에픽 6개 모두 `after: []`, `blocks: []`**. `tickets.py`는 "에픽 파일 자신의 `after`가 엔트리의 것을 대체하고, 없으면 빈 값으로 읽는다"(스크립트 주석 14·34행, `raw_after`는 파일 frontmatter에서 읽음). 즉 `tickets.toml`에 적은 1←2←3, 2·3←4, 4←5, 4←6은 **도구에 보이지 않는다**. `longest_remaining_chain`이 빈 것도 이 때문이다.
- 정상인 점: `tickets: []`, `counts.total: 0`, `status: ""`는 스토리·플랜이 없는 단계에서 당연하다. `unpinned_after: []`도 스토리가 없어 비어 있는 것이고 경고가 아니다.
- 스키마 오류·중복 id·고아 slug는 없다(스크립트가 통과). 에픽 파일 covers와 `tickets.toml` covers는 6개 모두 일치한다.

## fix

1. **에픽 파일 frontmatter `after`를 채운다.** 6개 모두 `after: []`라서 보드가 순서를 모른다. `epic-capture: after: [1]`, `epic-log-and-context: [2]`, `epic-recall-and-mirror: [2, 3]`, `epic-operations: [4]`, `epic-embedding-index: [4]`로 `tickets.toml`과 일치시킨다(엔트리의 `needs` 문구는 그대로 두면 된다).
2. **epic-capture Done when 4의 "미러"를 뺀다.** 미러는 AD-16·CAP-13으로 epic 4 소유이고 epic 2의 `after`에 없다. epic 2는 "저장 본문과 이후 내보내기에 그 값이 없다"로 좁히고, "가린 세션의 미러 재생성"(AD-11)은 epic 4 Boundaries·Done when으로 옮긴다.
3. **epic-log-and-context Done when 3의 "근거 대화로 내려간다"를 자기 경계로 좁힌다.** 원문 읽기는 `sessions read`·`recall expand`(AD-5, epic 4)이고 epic 4는 epic 3 뒤다 — 그대로 두면 순환이다. epic 3은 "대체 체인과 `anchor_seq`가 기록되고 그 출처 값으로 원문 위치를 지목한다"까지로 하고, CAP-3 success "로그 한 줄에서 앞뒤 메시지를 읽을 수 있다"의 소유를 epic 4 Done when에 적는다(또는 epic 3이 최소 `sessions read`를 갖는다고 명시 — ask 2).
4. **`workspaces`와 `sessions assign-workspace`에 주인을 준다.** Table Contract의 `workspaces`(작성자: 사람), FR-4·FR-24·AD-12·UJ-6이 요구하지만 어느 봉투에도 없다. `projects`·`worktrees`(및 `worktrees.removed_at`을 drain이 채우는 일)도 epic 2 Boundaries의 테이블 목록에 빠져 있는데 Done when 5가 그 동작을 시험한다. epic 2 Boundaries에 `projects, worktrees, workspaces`를 추가하고 `assign-workspace`를 Description·Done when에 넣는다.
5. **`sessions failures`·`sessions retry`에 주인을 준다.** AD-5 표와 FR-24("수집 실패 조회와 다시 수집")·FR-25의 항목인데 어느 에픽의 Description·Done when에도 없다(`failures` 테이블만 epic 2에 있다). epic 2에 넣고 "실패를 만들고 `sessions retry`로 해소된다"를 확인 문장으로 쓴다.
6. **`admin reindex`와 CAP-4 success를 epic 4에 넣는다.** 현재 `admin reindex`는 epic 6 Description에만 있다. CAP-4/FR-11의 "색인을 비우고 다시 만들어도 원문·로그·출처가 변하지 않고 점수가 떨어지지 않는다"와 "조각은 메시지 경계를 지키고 원문을 그대로 담는다"는 키워드 기본 구성의 일이므로 epic 4가 가져야 한다(epic 6은 모델·차원 교체분만).
7. **doctor 항목의 추가 주체를 에픽마다 명시한다.** FR-25·AD-9·AD-17·AD-19·AD-20이 요구하는 점검 항목이 흩어져 있는데 epic 1은 "기본 점검"만 말하고 나머지 에픽은 doctor를 말하지 않는다. 배분 제안: 미수집 세션·실패한 수집·spool 건수와 가장 오래된 시각·Harness별 마지막 hook 수신 시각 → epic 2; 대조되지 않은 규칙 인용·규칙 크기 경고·세션 수 대비 주입 시도 수 → epic 3; 실패한 색인·색인 설정 → epic 4(모델·차원은 6); 마지막 내보내기 시각 → epic 5(이미 있음); 실패한 재순위 → epic 6. 각 Boundaries에 "doctor에 내 항목을 더한다" 한 줄.
8. **hook 이중 등록 금지를 Done when으로 만든다.** CAP-11 success "재설정을 반복해도 hook이 중복 등록되지 않는다"와 AD-19의 Brain 표식 판정이 어느 Done when에도 없다. `setup connect`는 epic 2 소유이므로 epic 2 Done when에 "`setup connect`를 두 번 돌려도 `~/.claude/settings.json`의 Brain 표식 항목이 하나다"를 넣는다(epic 1 Done when 4는 hook이 없는 상태의 멱등성만 본다).
9. **경고 코드 `UNINDEXED`와 `CURSOR_RESET`에 주인이 없다.** Conventions의 9개 코드 중 7개는 주인이 있다(SPOOLED 2·3, DB_UNAVAILABLE 1, SCHEMA_MISMATCH 5, RERANK_FAILED·INDEX_CONFIG_MISMATCH 6, RESULT_TRUNCATED 4, RULE_UNVERIFIED 3-암시). `UNINDEXED`(AD-15, NFR-2의 "빈 결과를 성공으로 돌려주지 않는다") → epic 4, `CURSOR_RESET`(AD-4의 커서 fingerprint 불일치 재읽기) → epic 2 Done when에 추가.
10. **`brain log`·`brain recall` 직전 증분 수집(AD-6, AD-4 대체 경로)을 epic 4에 적는다.** epic 4 Boundaries는 AD-13·15·16만 든다. AD-6을 추가하고 "transcript가 있으면 recall 전에 그 세션이 먼저 수집된다"를 확인 문장으로 둔다(epic 3도 `log append` 쪽으로 같은 문장 필요).
11. **SM-7 실측의 주인이 없다.** spec Assumptions("첫 구현에서 실측해 확정")·NFR-7·AD-6이 요구하지만 어느 Done when에도 측정이 없다. 시작 맥락 지연 → epic 3, 시간·내용 조회 지연 → epic 4의 Done when에 "중앙값을 재고 기록한다"로 넣는다(값 미달이 곧 실패는 아니고 기록이 조건).
12. **Model Studio 외부 전송이 initiative Touch point 목록에 없다.** 기본 구성은 외부 전송 0(NFR-6)이지만 epic 6이 켜는 순간 외부 경계가 생긴다. initiative Boundaries에 "Touch point: Model Studio API — 임베딩·재순위만, 기본 꺼짐; owner: epic-embedding-index" 한 줄을 추가한다.
