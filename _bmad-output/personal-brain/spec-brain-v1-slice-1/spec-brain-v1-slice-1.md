# Personal Brain V1 slice 1 — 수집하고, 적어 두고, 찾는다

읽는 법: 이 커널의 CAP이 기준이다. FR별 testable consequences는 PRD에, 구현 불변식(AD-1~28, Table Contract)은 architecture spine에 있다. 둘 다 companion이며 그대로 따른다. addendum은 SM-3 확장 채점표(§8)와 규모 시험 결과(§1)를 위해 읽는다. spine과 다르면 spine이 우선한다.

## Why

새 AI 세션을 열 때마다 규칙, 최근 작업, 문서 위치를 다시 설명해야 한다. 예전 결정이 왜 그렇게 됐는지 찾으려면 기억에 의존해야 한다(pain). Brain은 어떤 에이전트와 Harness를 쓰든 나라는 사람의 작업 기억을 하나로 이어 준다(vision). slice 1은 그 최소 형태다. Claude Code 세션을 자동으로 수집하고, 일하는 에이전트가 결정·규칙·진행·선호를 그 순간에 한 줄로 적고, 넓은 것에서 좁은 것(원문)으로 찾는다. 개인용으로 먼저 검증한다. 멀티레포 팀의 맥락·결정 공유는 그다음이다.

## Capabilities

- **CAP-1 세션 자동 수집** (FR-1~6)
  - **intent:** Claude Code 세션의 대화 본문, 도구 메모, 추적 정보가 내 조작 없이 턴마다 Brain에 쌓인다. 꼬리표(워크스페이스·프로젝트·워크트리)가 자동으로 붙는다.
  - **success:** 이 기계의 Claude Code 세션 수와 Brain 세션 수의 차이가 0(SM-5)이다. 같은 세션을 두 번 넣어도 모든 테이블의 건수가 같다. 비정상 종료한 세션도 마지막 턴까지 남는다. 같은 레포의 다른 워크트리는 한 프로젝트로 묶인다.
- **CAP-2 비밀 가리기** (FR-26)
  - **intent:** 대화에 들어간 키·토큰·비밀번호가 Brain에 남지 않는다.
  - **success:** 알려진 패턴의 비밀이 든 세션을 수집하면 저장 본문에 그 값이 없다. 저장된 메시지의 일부를 가리면 DB·미러·내보내기 어디에도 원래 값이 남지 않고, 위치·종류·시각만 남는다.
- **CAP-3 작업 로그와 대화 연결** (FR-7~9)
  - **intent:** 일하는 에이전트가 진행·결정·규칙·선호를 그 순간에 한 줄로 적고, 그 줄에서 바로 나온 대화로 내려간다.
  - **success:** 로그가 있는 세션이 80% 이상(SM-4a)이다. 표본 세션의 결정 중 80% 이상이 로그에 있다(SM-4b). 로그 한 줄에서 앞뒤 메시지를 읽을 수 있다. DB가 꺼져 있을 때 적은 로그도 연결 후 빠짐없이 들어간다.
- **CAP-4 색인** (FR-10~11)
  - **intent:** 메시지가 검색 가능한 조각으로 묶이고, 색인은 원문과 작업 로그만으로 언제든 다시 만들어진다.
  - **success:** 색인을 비우고 다시 만들어도 원문·로그·출처가 변하지 않고, 채점표 점수가 떨어지지 않는다. 조각은 메시지 경계를 지키고 원문을 그대로 담는다.
- **CAP-5 시간 조회** (FR-12)
  - **intent:** 날짜 범위로 그 기간에 한 일을 프로젝트를 가리지 않고 시간순으로 받는다.
  - **success:** "어제·지난주·특정 날짜" 질문의 90% 이상이 실제와 맞는다(SM-2). 기록이 없는 기간에는 빈 결과를 돌려준다. LLM·임베딩 호출이 없다.
- **CAP-6 내용 검색** (FR-2, FR-13, FR-14)
  - **intent:** 작업 로그(대분류), 대화 조각(소분류), 도구 메모(파일 경로)를 내용으로 찾고, 가까운 꼬리표의 결과가 먼저 나온다.
  - **success:** SM-3 채점표(기존 10문항 7개 이상, 추가 8문항 4개 이상)를 기본 구성(키워드 + 에이전트의 질의 바꾸기)으로 통과한다. 파일 경로로 그 파일을 다룬 세션들이 나온다. 한국어 질의로 영어 대화를 찾는다.
- **CAP-7 넓히기와 출처** (FR-15~16)
  - **intent:** 모든 결과에 근거 세션·위치·날짜·꼬리표가 붙고, 거기서 앞뒤 조각, 세션 전체, 도구 메모로 넓힌다.
  - **success:** 어떤 결과든 출처 값만으로 원문까지 내려간다. 한 번의 결과는 8,000자를 넘지 않는다(SM-C2).
- **CAP-8 시작 맥락** (FR-17~18)
  - **intent:** 세션이 시작되면 오늘 날짜·시간대, 켜진 규칙, 가까운 곳의 최근 작업 로그, 사용 안내가 자동으로 들어간다. 이후 프롬프트에는 아무것도 덧붙이지 않는다.
  - **success:** 전날 작업한 프로젝트에서 "이어서"만으로 이어간 비율이 80% 이상(SM-1)이다. 주입 시도가 성공·실패 모두 기록된다. Brain이 꺼져 있어도 세션은 막히지 않고, 그 사실이 보인다.
- **CAP-9 규칙·결정·선호 관리** (FR-19~22)
  - **intent:** 규칙은 내 발화의 인용으로만 켜지고, 결정·선호는 대체되어도 사라지지 않으며, 나는 이것들을 조회·수정·끄기 할 수 있다.
  - **success:** 원문과 대조되지 않은 규칙은 주입되지 않는다. 내가 끈 규칙은 자동으로 다시 켜지지 않는다. "처음엔 뭐였지"에 대체된 결정이 근거 대화와 함께 답한다. 수정 이력이 모두 남는다. 같은 뜻의 규칙을 다시 말하는 횟수가 주 1회 이하(SM-6)다.
- **CAP-10 SDK와 CLI 도구** (FR-23~24)
  - **intent:** 모든 기능을 SDK 하나(`second_brain`)로 쓰고, 에이전트와 나는 같은 기능을 Harness에 묶이지 않는 CLI로 쓴다.
  - **success:** spine AD-5 표의 slice 1 명령(epic 9 예약 행 `mcp`·`daemon` 제외)이 모두 있고, 각각 `--json`과 사람용 출력을 낸다. 명령 메타에서 `admin schema`가 나오고, 확인이 필요한 명령은 비대화형에서 종료 코드 3으로 멈춘다. CLI·hook에 SDK를 거치지 않는 경로가 없다. Core 패키지에 외부 런타임 의존성이 없다.
- **CAP-11 설치·설정·점검·운영** (FR-25)
  - **intent:** 대화형 설치기 하나로 의존성, DB, 미러 경로, 임베딩, Harness 연결을 묻고 설치한다. 언제든 다시 설정하고, 업그레이드하고, 제거하고, 상태를 점검한다.
  - **success:** 빈 Mac에서 설치기 한 번으로, 또는 Claude Code 플러그인을 켜면 첫 세션이 설치를 시작하고(그 세션은 설치가 끝난 뒤 폴더 스캔으로 수집) 다음 세션부터 hook으로 수집된다. 재설정·플러그인 갱신을 반복해도 hook은 하나다. 점검이 FR-25 항목과 spool·스키마 버전·마지막 hook 수신 시각·플러그인 버전 일치를 보여 준다. 제거 후 Brain hook이 남지 않는다.
- **CAP-12 내보내기와 복구** (NFR-9)
  - **intent:** 모든 원문과 작업 로그를 Brain 없이 읽을 수 있는 형식으로 내보내고, 그것에서 되살린다.
  - **success:** 되살린 뒤 메시지 수와 작업 로그 수가 내보내기 전과 같다. 내보내기가 설정한 기간보다 오래되면 점검이 경고한다.
- **CAP-13 Markdown 미러**
  - **intent:** 세션마다 사람이 열고 어떤 에이전트든 grep할 수 있는 Markdown 파일이 내가 정한 폴더에 생긴다.
  - **success:** 미러를 지우고 다시 만들면 같은 내용이 나온다. Brain 도구 없이 grep만으로 세션을 찾을 수 있다. 미러를 고쳐도 DB는 변하지 않는다.
- **CAP-14 첨부 원본과 문서 찾기** (FR-27, FR-28)
  - **intent:** 대화에 붙인 파일이 원본째 남고, 문서는 본문 단어와 경로·파일 이름으로, 사진은 경로와 촬영 일시로 찾힌다.
  - **success:** 첨부가 있는 메시지에서 원본 위치를 받아 다시 열 수 있다. 같은 내용은 한 번만 보관된다. 문서 본문의 단어로 그 문서와 쪽이 나온다. 내용을 읽지 못한 문서는 표시된다. 사용자의 기존 파일은 Brain이 옮기거나 지우지 않는다.

## Constraints

- 원본 저장소는 로컬 SQLite 파일 하나다. 복제 대상(Postgres·Drive)은 원본을 따라올 뿐 원본이 아니다. 미러·조각·색인은 파생물이다(AD-10).
- 구현 언어는 TypeScript, 실행 환경은 내 Mac 한 대. slice 1에는 상주 프로세스가 없고, 데몬은 epic 9에서 선택으로 더하며 데몬 없이도 전부 동작한다(AD-5, AD-6, AD-25, AD-27).
- Brain은 LLM을 부르지 않는다. 기본 구성의 외부 전송·비용은 0이고, 임베딩·재순위는 선택이다(NFR-5, NFR-6, AD-15).
- 원문은 저장 후 바뀌지 않는다. 유일한 예외는 비밀 가리기다(NFR-1, AD-11).
- 실패는 조용히 지나가지 않는다. 저하된 결과는 반드시 경고 코드와 함께 돌려준다(NFR-2).
- Brain의 지연·장애가 Harness의 시작과 종료를 막지 않는다(NFR-3).
- 조회는 한국어에서 동작해야 한다(NFR-4).
- Harness를 가리지 않는다. 새 Harness는 parser 하나로 붙는다(AD-4).
- 키는 저장소 밖에 두고, 공개 저장소에는 회사 이름·내용·실제 대화를 넣지 않는다(AD-18).
- slice 1을 설정하기 전에, 노출된 적이 있는 Model Studio API 키를 다시 발급한다.

## Non-goals

- 대화를 사실 문장으로 다시 쓰는 추출·통합 엔진, LLM 세션 요약, LLM 주제 분류
- 프롬프트마다 맥락을 밀어 넣는 것
- 규칙을 Harness 지시 파일(CLAUDE.md 등)에 복사하는 것
- slice 1에서의 팀 공유·다중 사용자, Claude Code 외 Harness 수집, 과거 세션 가져오기, 두 번째 기계. MCP·데몬은 slice 1 밖이지만 epic 9로 계획한다(2026-10-15)
- Harness 원본 transcript와 도구 출력 보관

## Success signal

명훈이 2주 동안 실사용하는 기간 내내, 새 세션에서 "어제 하던 거 이어서"라고만 해도 다시 설명하지 않고 이어간다(SM-1 ≥ 80%). "지난주에 뭐 했지", "그거 왜 그렇게 했지"에는 날짜와 근거 대화가 붙은 답이 나온다(SM-2 ≥ 90%, SM-3 통과). 이 동안 Brain은 LLM을 한 번도 부르지 않는다.

## Assumptions

- Orca·Paseo 안에서 돌린 Claude Code 세션은 Claude Code 세션으로 수집된다.
- "이어받은 세션" 관계는 자리만 두고 slice 1에서 채우지 않는다.
- 지연 목표(내부 0.5초·0.1초, 전체 1초·0.5초·3초)는 여유값이고, 첫 구현에서 실측해 확정한다(SM-7).
- 시작 맥락 크기 600자·1,000자, 결과 8,000자, 세션당 로그 중앙값 10줄 이하, 외부 비용 월 10달러 이하는 추정값이다(SM-C1~C3, SM-8).

## Open Questions

- 작업 로그가 없는 세션이 많을 때 LLM 세션 요약을 안전망으로 넣을지: SM-4 결과를 보고 판단(PRD §8-1)
- BMad memlog와 작업 로그를 연계할지(PRD §8-2)
- 시작 맥락 안내만으로 기록 규율이 충분한지, 더 강한 수단이 필요한지(PRD §8-3, SM-4)
- 대분류 먼저 검색이 조각 직접 검색보다 실제로 나은지(PRD §8-5)
- 내가 과거를 언급했을 때 에이전트가 스스로 조회하는지(PRD §8-8, SM-1)
