작성일: 2026-11-02, Asia/Seoul. 이 문서는 대화 인계 기록이며 티켓의 완료 증거나 새로운 승인된 구현 계획이 아니다.

## 다음 세션의 목적

자동 루프를 재개하지 않고, 사람이 범위를 결정하며 한 티켓씩 에이전트와 진행한다. 먼저 현재 미완성 작업을 보존하고 16.2의 과도한 보안 확장과 기존 기능의 변경을 구분한다. 이후 14.6 마무리와 축소한 16.2의 새 계획을 진행하는 순서를 제안했다.

이번 세션에서 수행한 것은 조사, 종료 제어, 이 인계 문서 작성이다. 14.6·16.2의 제품 코드 수정, 범위 축소, 원복, 티켓 드랍 또는 완료 처리는 하지 않았다.

## 사용자 지시와 논의의 구분

명시적인 사용자 지시:

- 현재 작업이 끝나면 루프를 종료한다.
- 앞으로는 사람이 계속 진행한다. 감독자가 미완료 티켓을 끝까지 자동 복구하는 방식은 계속하지 않는다.
- 다음 세션용 인계 문서를 만든다.
- 공개 저장소이므로 문서·계획·리뷰·커밋 메시지·다른 에이전트 프롬프트에 실명 홈 절대 경로를 쓰지 않는다. `~/…`, `<repo>/…`, 저장소 상대 경로를 사용한다.
- `plugin/app-ref`를 바꾸면 `plugin/.claude-plugin/plugin.json`의 version도 함께 올리고, app-ref는 이를 변경하는 커밋보다 앞선 커밋을 가리킨다.

논의한 방향과 제안 — 아직 계획·코드에 적용하지 않음:

- 사용자는 개인용 데몬에 현재 추가된 수준의 보안이 필요한지 의문을 제기했다.
- 권고는 16.2 전체 기능을 버리는 대신, 같은 UID 악성 프로세스 방어를 위한 공통 보안 확장을 제외하고 원래 Garmin 인증·호출 보호 범위로 축소하는 것이다.
- 기존 긴 세션에 “이것만 해”를 덧붙이기보다, 요구사항과 검증 기준을 먼저 수정하고 새 세션에서 구현한다. 계획에 보안 요구가 남으면 리뷰가 다시 미충족으로 판정한다.
- 변경 분리·원복의 실제 대상은 아직 확인·결정하지 않았다. 이 문서를 전체 reset/delete 실행 지시로 해석하지 않는다.

## 14.6 — 왜 멈췄고 무엇이 남았는가

목적은 `brain ext run garmin import-verify`: 원본 capture와 반입 결과를 전수 대조하고, private 상세와 개인 값 없는 공개 집계를 생성하며 불일치 시 실패시키는 것이다.

11월 1일 실행:

- 05:24–06:54: dev-1, 90분 timeout.
- 06:57–08:27: dev-2, 다시 90분 timeout.
- `max_dev_attempts=2` 소진으로 deferred. 이후 16.1로 넘어갔다.

다섯 차례 리뷰에서 합계 15개 finding이 기록됐다. JSON bool/number, Node·Python DB decoder·metadata bytea의 정밀도, timestamp 마이크로초, 이전 batch의 논리 범위, 파일 경합 등의 문제를 반복 교정했다.

`bmad-build/step-04-review.md`는 `bad_plan`이면 KEEP을 추출하고 코드를 되돌린 뒤 계획 수정·재도출을 요구한다. 실제로 15–19개 파일의 보존·원복·복원과 독립 검증을 반복했다. 기본 약 3,900개 시험의 측정 시간은 회당 약 82초여서 전체 지연을 단순 시험 속도 문제로 설명할 수 없다.

리뷰5의 미해결 세 항목:

1. input/artifact의 `metadata_raw`를 float로 해석하면서 정밀 소수 변조가 원래 값과 같다고 판정된다. canonical display/raw 양쪽 대조가 필요하다.
2. legacy notification/delivery의 `original_key_label`, `_raw`, `_encoding` 검사 누락. 정상 발행자의 NULL 계약과 대조해야 한다.
3. 대형 evaluation inventory의 `metadata_raw`, `unlinked_reason` 검사 누락. 정상 NULL 계약 및 변조 실패를 검증해야 한다.

**중요:** `apps/cli/python-test/garmin-import-verify.test.ts`에는 정밀 raw 숫자를 변조해도 exit 0·inventory=true가 되는 **수정 전 오판을 기대하는 임시 재현 시험**이 남아 있다. 수정 후에는 실패·inventory=false를 기대하도록 바꿔야 한다. 현재 시험 통과만으로 정확성을 주장하지 않는다.

## 16.2 — 범위가 커진 이유와 축소 제안

원래 티켓은 Garmin 로그인·MFA·토큰 저장, 403/429·인증 실패 이후 영속 차단, 재인증/다음 날 probe/수동 해제, 호출 간격, 같은 계정의 인증·수집 직렬화, 비밀 비노출을 요구한다.

첫 실행에서 인증 비밀 전달·상대 신원 계약 공백이 발견됐고, 감독자는 “같은 UID의 미승인 프로세스도 방어”하는 위협 모델을 추천안으로 채택했다. 이는 원래 0700/0600·비밀 비노출보다 훨씬 넓다. 이후 코드 서명·native C 실행기·보호 UI/broker·전용 FD·root 소유 registry·별도 principal·DB 자격 격리·공통 queue 통신 재설계로 확장됐다.

11월 1일 08:53–16:28, 약 7시간 35분 동안 최초 실행 포함 7개 세션(g0–g6)을 거쳤다. 인증 transport, 보호 배치, OS 승인 단위의 설계 공백과 한 차례 worker DNS 초기화 오류를 해소하며 재개했고, g4·g5·g6은 각각 90분 timeout이었다. 이는 14.6의 리뷰 재도출 반복과 구분한다. 16.2 계획의 review iteration은 0이며 중단 원인의 중심은 보안 설계 확장과 부분 구현이었다.

유지할 범위로 제안한 것:

- 라이브러리 login/dump와 동일 client의 MFA, tokenstore.
- 비밀번호·MFA·토큰의 argv·로그·결과 비노출 및 기본 파일 권한.
- Garmin 호출 제한·계정 보호 상태, 재시작 후 유지, 동일 계정 직렬화.

제외할 범위로 제안한 것:

- 같은 UID 악성 프로세스 방어를 위한 실행물 서명·봉인 registry·root 설치·별도 principal.
- 이 목적만으로 추가한 native 보안 실행기, 승인 broker, 공통 queue/DB 접근 구조 변경.

축소 시 먼저 확정할 전제:

> 개인용 로컬 데몬이며 현재 OS 사용자와 그 사용자가 실행한 프로그램은 신뢰한다. 같은 UID 악성 프로세스에 대한 격리는 범위에서 제외한다. 자격증명 비노출과 Garmin 계정의 호출 보호는 유지한다.

위 내용은 논의한 제안이다. 실제 계획·아키텍처·수락 기준이 아직 이를 반영하지 않으므로, 구현 전에 서로 충돌하는 요구를 정리한다. 기존 공통 기능까지 무조건 제거하거나 현재 partial 구현을 built/done으로 간주하지 않는다.

## 앞선 메모리·플러그인 논의 — 아직 별도 작업으로 실행하지 않음

이번 대화 앞부분에는 Brain의 기억 사용 방식에 관한 논의도 있었다. 당장의 14.6·16.2 정리와 섞어 구현하지 않는다.

- 원문 수집과 중요한 기억은 별개다. `messages` 원문과 `log_entries`(progress/decision/rule/preference), 검색용 chunks 구조가 있고, 테이블 존재가 기능 완성을 뜻하지 않는다.
- 사용자는 “앞으로 …” 같은 지속 지침, 확정 결정, 구체적인 교정만 선별 저장하고 컨텍스트를 보호하기를 원했다. 막연한 불만·일회성 요청·에이전트 추측은 장기 기억으로 자동 확정하지 않는 방향을 논의했다.
- 조회는 과거 정보 사용 요청 때만 하는 방향을 논의했다. “지난번 결정대로”도 자연어 요청으로 인정하면 별도 CLI 지시를 반복할 필요는 없다. 요청이 전혀 없어도 개인화를 원한다면 일부 자동 조회를 허용해야 한다는 절충은 남아 있다.
- 대상은 Codex·Claude Code CLI와 각각 데스크톱, 일반 데스크톱 채팅까지다.
- 데몬·SDK·DB는 유지하고, 일반 채팅용 MCP를 얇은 연결층으로 제공하는 방안을 권고했다. MCP 자체가 전체 대화를 수집하거나 매 턴 자동 기록을 보장하지는 않는다.
- 스킬은 사용 절차를, 도구 설명은 호출 방법을 제공한다. “언제 사용”이라는 짧은 지침을 코딩 에이전트 전역 파일에 설치기가 관리 구역으로 넣는 방안을 논의했다. 일반 채팅 계정 지침 자동 변경은 확인되지 않아 별도 최초 설정 안내가 필요할 수 있다.
- CLI/Code, 일반 Chat, 로컬 실행/클라우드 실행의 기능을 혼동해 앞선 답변에서 단정했다가 정정한 이력이 있다. **플러그인 설치 가능, 셸 실행 가능, hook 실행 가능, 일반 채팅 시작 지침 자동 주입은 각각 따로 검증해야 한다.** 제품 기능이 바뀌므로 재개 시 공식 문서와 실제 앱에서 다시 확인한다.
- 이 논의로 전역 AGENTS.md/CLAUDE.md, 계정 지침, MCP, 기존 기억 계획을 변경한 것은 없다.
