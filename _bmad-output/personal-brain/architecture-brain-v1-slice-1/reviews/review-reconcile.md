## 2. (a) 빠진 것과 모순 — 넣어야 하는 것

### F-1 [High · 모순, memlog 미설명] 한국어 질의로 영어 대화를 찾는 경로가 사라졌다

- **PRD**: FR-14 Consequence — "한국어 질의로 한국어·영어 대화를 찾는다." NFR-4 — "조회는 한국어에서 동작해야 한다." §9 — "한국어 검색 품질은 사전 시험의 기준선 구성(다국어 임베딩, 다국어 재순위)을 출발점으로 삼는다."
- **spine**: AD-15 — "기본 검색은 키워드(Postgres `pg_trgm`)다. 임베딩·재순위는 port 뒤의 선택 색인이고 **slice 1 기본값은 꺼짐**이다."
- **문제**: `pg_trgm`은 n-gram 문자열 유사도다. 번역을 하지 않으므로 "인증 흐름"이라는 한국어 질의로 `passkey recovery`가 영어로만 적힌 조각을 찾는 일은 **기본 구성에서 구조적으로 불가능**하다. FR-14의 저 Consequence는 슬라이스 1의 기본값에서 테스트가 통과할 수 없다. UJ-3(한국어로 묻고 영어 문서를 찾는 여정)이 바로 이 경로다.
- **memlog 대조**: memlog 55가 "검색: 키워드 기본 … 임베딩·재순위는 설정으로 켜는 선택 색인, slice 1 기본 꺼짐"을 결정하고, memlog 58-(4)가 "임베딩 선택·기본 꺼짐에 따라 NFR-4/NFR-6/SM-3 **문구 조정**"을 PRD 갱신 목록에 올렸다. 그러나 (i) 목록은 NFR-4의 *문구*만 다루고 FR-14의 교차언어 Consequence는 언급하지 않으며, (ii) 문구를 고쳐도 "한국어에서 동작해야 한다"는 요구 자체는 남는다. memlog 43의 규모 시험도 A(파일+grep) 13.5/16으로 "충분"을 보였지만, 그 시험의 검색 주체는 **여러 번 질의를 바꿔 넣는 LLM 에이전트**였다. 즉 교차언어를 메운 것은 색인이 아니라 에이전트의 재질의다.
- **넣어야 하는 것**: AD-15에 한 줄 — "교차언어 조회의 책임은 에이전트의 재질의(원어/영어 키워드 병행)에 있고, Brain은 그 전제를 시작 맥락 안내와 `--json` 응답에 명시한다. 임베딩을 켜면 색인이 그 역할을 대신한다." 그리고 NFR-4의 "영어 전용 임베딩·재순위면 점검이 실패로 표시"는 **port 수준 규약**으로 살려야 한다(addendum §3 재순위 행: "영어 전용 모델로 대체하지 않는다(NFR-4)"). 현재 spine의 doctor 목록에 이 검사가 없다.

### F-2 [High · 빠짐] 지연 예산(NFR-7/SM-7)을 지킬 구조가 없다

- **PRD**: NFR-7 — "시작 맥락은 세션 시작을 체감할 만큼 늦추지 않는다." SM-7 — 시작 맥락 1초, 시간 조회 0.1초, 내용 조회 3초(중앙값).
- **spine**: AD-6만 NFR-7을 binds하고, 규칙은 "네트워크(임베딩·재순위)는 동기 경로에 두지 않는다"뿐이다. AD-19가 "`npx` 지연으로 hook이 느려지는 것"을 막는다.
- **문제**: paradigm이 "데몬 없는 단명 CLI"다. 따라서 **턴마다, 세션마다 새 프로세스가 Node 부팅 + Docker Postgres TCP 연결 + 첫 쿼리를 다시 치른다.** 이것이 1초 예산의 주된 소비처인데 spine 어디에도 규율이 없다. 커넥션 풀을 띄울지(단명 프로세스에서는 손해), 단일 커넥션으로 갈지, `brain context`가 읽는 쿼리 수를 몇 개로 묶을지, 시작 맥락이 느려졌을 때 무엇을 포기할지(타임아웃 시 빈 주입 + 기록)가 전부 미정이다.
- **memlog 대조**: memlog 14가 **이 문제를 알아보고 미뤘다** — "사용자: 묶음 import 비용(전 모듈 로드)은 문제 아님에 동의. 실제 지연 원인은 PG 연결·첫 쿼리 → **실행 형태에서 다룸**." 실행 형태(AD-5·AD-6)는 결국 이 약속을 지키지 않았다. memlog 60이 hook의 `npx` 지연만 처리했다.
- **넣어야 하는 것**: AD 신설 — "단명 프로세스의 지연 예산". 내용 후보: 시작 맥락 경로는 커넥션 1개·쿼리 N개 이하, 풀 금지, `brain context`의 동기 timeout 값과 **초과 시 빈 주입 + 실패 기록**(FR-17 "Brain이 응답하지 않으면 세션은 주입 없이 시작되고 그 사실이 기록된다"의 실행 지점), 턴 수집(`Stop`)은 async이므로 예산 밖. 수치 자체는 spec 몫이어도 **예산을 어디서 지키는지**는 아키텍처 고도다.

### F-3 [Medium-High · 빠짐] 쓰기 API 둘의 분리 — "hook은 로그를 쓸 수 없다"가 사라졌다

- **PRD/addendum**: addendum §5 (사용자 확인) — "**쓰기 API는 둘로 나눈다**: 대화 쌓기(`sessions.ingest` — hook이 호출, 멱등)와 로그 쌓기(`log.append` — 에이전트가 호출, 한 줄). **로그는 hook이 쓸 수 없다. 문장을 쓰는 것은 에이전트다.**" PRD §6.1 Non-Goal — "Brain이 뒤에서 LLM으로 세션을 요약하지 않는다. 적는 것은 일하는 에이전트다." FR-7 — "적는 데 Brain의 LLM 호출이 없다."
- **spine**: AD-5가 "SDK 메서드·CLI 명령·MCP 도구 1:1"을 말하고 AD-6이 수명주기를 매핑하지만, **두 쓰기 경로의 분리와 "자동 경로는 로그를 쓰지 않는다"는 금지가 한 줄도 없다.**
- **문제**: memlog 9가 이 제약을 "PRD 상속(재결정 안 함)"으로 명시했는데 spine이 상속을 적지 않았다. 이 금지가 없으면 drain이나 hook이 "진행 로그를 자동으로 한 줄 적는" 편의 기능을 넣는 것이 구조적으로 막히지 않는다 — 그러면 SM-4(로그가 실제로 적히는가)의 측정값이 오염되고, PRD의 핵심 Non-Goal이 무너진다. slice 1의 최대 위험이 SM-4라고 memlog 55가 적었으므로 측정 오염은 치명적이다.
- **넣어야 하는 것**: AD 신설 또는 AD-5 확장 — "쓰기 경로는 둘뿐이다. `sessions.ingest`(멱등, 자동 경로가 호출) / `log.append`(에이전트가 호출). 자동 경로(hook·drain·설치기)는 `log_entries`에 문장을 쓰지 않는다. drain이 채우는 것은 파생 칸(대화 연결, 인용 위치, 색인)뿐이다."

### F-4 [Medium-High · 모순, memlog 미설명] 규칙의 "적용 범위"가 AD-12와 충돌한다

- **PRD**: Glossary "적용 범위" — "규칙이 주입되는 곳. 기본은 어디서나이고, 한 프로젝트로 제한할 수 있다. **꼬리표(출처)와는 별개다.**" FR-19 — "적용 범위는 기본이 어디서나다 … 어느 프로젝트에서 나온 규칙인지는 꼬리표로 남는다. 적용 범위와 꼬리표는 별개다." FR-22 — "규칙의 적용 범위를 바꿀 수 있다." addendum §2 — `log_entries.only_project_id?`(적용 범위 제한이 있을 때만).
- **spine**: AD-12 — "워크스페이스·프로젝트·워크트리 꼬리표는 `sessions`에만 둔다. **로그와 조각은 `session_id`로 따라간다.** [ADOPTED]"
- **문제**: `log_entries.only_project_id`는 로그 행에 붙는 프로젝트 참조다. AD-12를 글자대로 읽으면 금지되고, 그러면 FR-19/FR-22의 적용 범위 제한을 구현할 자리가 없다. 반대로 허용하면 AD-12가 막으려던 "꼬리표의 두 번째 진실"과 구별이 모호해진다. spine 어디에도 적용 범위라는 개념 자체가 등장하지 않는다(AD-17은 "켜진 규칙"만 말한다). 시작 맥락 조립(FR-17: 어디서나 규칙 + 현재 프로젝트 규칙)이 이 칸에 직접 의존한다.
- **memlog 대조**: memlog 31이 "[ADOPTED] 꼬리표는 sessions에만(addendum)"만 적었고 적용 범위 예외는 논의되지 않았다. 의도된 변경이 아니라 누락이다.
- **넣어야 하는 것**: AD-12에 예외 한 줄 — "**적용 범위는 꼬리표가 아니다.** 규칙의 적용 범위 제한(`only_project_id`)은 로그 행이 가지는 유일한 프로젝트 참조이고, 출처 꼬리표는 여전히 `session_id`로만 따라간다." 더불어 AD-17에 "시작 맥락의 규칙은 적용 범위로 고르고, 꼬리표로 고르지 않는다"를 덧붙여야 혼동이 끝난다.

### F-5 [Medium-High · 빠짐] 출처 표시(FR-16)와 꼬리표 근접 순서(FR-13/NFR-8)의 규약이 없다

- **PRD**: FR-16 — "**모든** 조회 결과는 출처를 가진다 … 결과에는 날짜와 꼬리표가 표시된다. 같은 주제의 옛 발언과 새 발언이 함께 나오면 날짜로 구분된다." FR-13 — "꼬리표가 있는 곳에서 조회하면 가까운 것이 먼저 나온다: 같은 워크트리, 같은 프로젝트, 같은 워크스페이스, 나 전체 순. **다른 프로젝트의 기록을 막지 않는다.**" NFR-8 — "꼬리표는 조회의 순서와 좁히기에만 쓰인다. 꼬리표 때문에 찾을 수 없는 기록이 있어서는 안 된다." FR-17 — "최근 작업 로그는 가까운 것부터 채운다."
- **spine**: FR-16은 **어느 AD의 Binds에도 없다**(Capability Map의 "조회 (FR-12~16)" 묶음에만 있다). Conventions의 `--json` 응답 규약은 `{ ok, data, warnings[], error? }`까지만 정하고 결과 항목의 모양을 정하지 않는다. AD-12는 꼬리표의 저장 위치만 정하고 조회에서의 쓰임(순서 전용·필터 금지)을 정하지 않는다.
- **문제**: 출처·날짜·꼬리표는 **모든 조회 반환의 공통 모양**이다. 따로 만들어지는 부분들(시간 조회, 대분류, 소분류, 넓히기, 미러)이 일관되어야 하므로 전형적인 규약 고도다. 지금처럼 비워 두면 조회마다 결과 모양이 갈라지고, "꼬리표로 필터링" 구현이 들어와도 아무 규칙을 위반하지 않는다.
- **넣어야 하는 것**: Consistency Conventions에 두 행 — (1) "조회 결과 항목은 `{ source: {session_id, 위치}, occurred_at, tags }`를 반드시 가진다"; (2) "꼬리표는 순위 가중치와 명시적 좁히기에만 쓴다. 기본 조회는 나 전체를 대상으로 하고 꼬리표로 결과를 제외하지 않는다(NFR-8)." 근접 순서(워크트리→프로젝트→워크스페이스→나)는 AD-15에 한 줄로 못 박는 것이 맞다 — 세 검색 경로가 같은 순서를 써야 하기 때문이다.

### F-6 [Medium-High · 빠짐] FR-3의 "이어받은 세션"과 addendum §2의 Execution 예약이 사라졌다

- **PRD**: FR-3 Consequence — "세션이 다른 세션을 이어받았다는 관계를 기록할 자리가 있다. `[ASSUMPTION: slice 1에서는 자리만 두고 자동으로 채우지 않는다]`" addendum §2 "세션과 실행의 분리" — "slice 1은 Harness 세션 하나를 세션 한 행으로 두지만, 실행 속성을 한 묶음으로 표시해 두고 `continuation_kind`·`work_context_id`를 예약해, **한 작업에 Harness 둘이 올 때 재설계가 되지 않게 한다.**" PRD §6.2 — "Codex … 에이전트 간 인계"는 다음 조각, "에이전트 실행 기록(Execution) … 저장 구조가 막지 않게 한다(addendum §2)."
- **spine**: ERD에 `sessions`의 자기참조(이어받음)가 없다. `continuation_kind`, `work_context_id`, Execution 분리 표시가 전부 없다. Deferred 표에도 Execution/Resource 행이 없다.
- **문제**: 이 예약은 "지금 안 만들지만 지금 자리를 둬야 하는 것"의 전형이고, 그래서 아키텍처 고도다(빠뜨리면 다음 조각에서 세션 테이블 재설계). spine이 Deferred에 "Codex 등 다른 Harness의 parser·hook — AD-4의 계약만으로 추가한다"고 적었는데, **AD-4의 계약은 입력 형식만 다루고 세션 계보는 다루지 않는다.** 즉 "AD-4만으로 추가 가능"이라는 주장이 Harness 인계 시나리오에서는 성립하지 않는다.
- **넣어야 하는 것**: AD-8이나 AD-12에 "세션 계보" 한 줄(`continued_from_session_id`, `continuation_kind`는 자리만 두고 slice 1에서 자동으로 채우지 않는다) + Deferred에 "Execution/Resource 분리 — addendum §2의 예약 칸으로 수용" 행.

### F-7 [Medium · 빠짐] FR-6(수집 경로 구분)이 binds에만 있고 실체가 없다

- **PRD**: FR-6 — "세션마다 수집 경로(실시간/가져오기)와 수집 시각이, 메시지마다 원래 발화 시각이 따로 기록된다. 발화 시각이 과거인 세션을 넣어도 시간 조회(FR-12)는 수집 시각이 아니라 **발화 시각**으로 답한다." addendum §2 — `ingest_source (live|import)`, `ingested_at` vs `messages.occurred_at` 분리.
- **spine**: AD-13이 FR-6을 binds하지만 내용은 "모두 `timestamptz` 절대 시각"뿐이다. 두 시각의 **분리**와 "시간 조회는 발화 시각으로"가 없다. ERD에도 흔적이 없다.
- **문제**: FR-6은 그 자체로 "지금 구조만 수용하고 기능은 나중"인 항목이다(PRD §6.2). 구조 수용을 적지 않으면 수용된 것이 없다. 그리고 "시간 조회의 기준 시각은 발화 시각"은 두 번 구현될 수 있는 선택이라 규칙으로 못 박아야 한다.
- **넣어야 하는 것**: AD-13에 두 줄 — "세션은 `ingest_source`(live/import)와 `ingested_at`을, 메시지는 `occurred_at`을 따로 가진다. **모든 시간 조회와 정렬의 기준은 `occurred_at`이다.**"

### F-8 [Medium · 빠짐] 조각 만들기 규칙(메시지 경계·머리말 금지)이 없다

- **PRD/addendum**: FR-10 — "조각은 메시지 경계를 지키고, 각 조각은 출처를 가진다 … **조각 본문은 원문 그대로다. 프로젝트 이름이나 날짜를 본문에 덧붙이지 않는다.**" addendum §1 — 조각 약 1,200자, 메시지 경계, **인접 겹침 1메시지**, 머리말 붙이지 않음(근거: "날짜·프로젝트를 본문에 넣으면 같거나 나빠짐. 꼬리표는 컬럼으로").
- **spine**: AD-15는 검색만 다룬다. 조각 생성 규칙이 없다. ERD에 `chunks`만 있다.
- **문제**: "머리말 금지"는 **시험으로 반증된 유혹**이다(붙이면 점수가 같거나 나빠짐). 규칙으로 적어 두지 않으면 구현자가 "검색이 안 되니 날짜를 붙여 보자"로 되돌아간다. 메시지 경계 유지는 FR-15(앞뒤 조각 넓히기)·FR-16(출처 위치)의 전제이기도 하다.
- **넣어야 하는 것**: AD-15나 Conventions에 — "조각은 메시지 경계를 지키고, 본문에 머리말(날짜·프로젝트·꼬리표)을 덧붙이지 않는다. 꼬리표는 컬럼·조인으로 붙인다. 크기 목표·겹침 수치는 spec(addendum §1)." 수치는 (b)지만 금지와 경계는 (a)다.

### F-9 [Medium · 빠짐] NFR-5(Brain은 LLM을 부르지 않는다)를 지키는 AD가 없다

- **PRD**: NFR-5 — "Brain은 slice 1에서 LLM을 부르지 않는다." FR-23 — "Core는 타이머, 서버, 프로세스를 소유하지 않는다. **LLM을 부르지 않는다.**" addendum §3 — "slice 1에는 LLM `Worker` 포트가 없다. 요약을 다시 넣게 되면 그때 추가한다." FR-1/FR-7/FR-12 — "수집/적기/시간 조회에 LLM 호출이 없다."
- **spine**: NFR-5는 어느 AD의 Binds에도 없고 Capability Map에도 없다. "LLM을 부르지 않는다"는 문장이 spine 전체에 한 번도 나오지 않는다. memlog 9가 "Brain은 LLM 미호출"을 상속 제약으로 적었는데 spine이 받지 않았다.
- **문제**: 이것은 제품의 정체성 제약이고(§6.1 Non-Goal 두 개가 여기 걸려 있다), "port가 없다"는 것 자체가 아키텍처 사실이다. 비워 두면 "요약 한 번쯤"이 port 추가 없이 adapter 안에서 생길 수 있다.
- **넣어야 하는 것**: AD-1이나 AD-3에 한 줄 — "Core의 port 목록에 LLM이 없다. Brain의 어느 경로도 LLM을 호출하지 않는다(문장을 쓰는 것은 호출한 에이전트다). 외부 호출은 선택 색인의 임베딩·재순위뿐이다."

### F-10 [Medium · 빠짐] 점검(doctor)이 FR-25의 목록을 덜 덮는다

- **PRD**: FR-25 — "점검은 **적어도** 다음을 보여 준다: 각 연결의 성공·실패, 색인 설정(모델, 차원), 미수집 세션, 실패한 수집·색인·주입·재순위, 대조되지 않은 규칙 인용, 규칙 크기 경고, 마지막 내보내기 시각." FR-5 — "다시 수집은 Harness가 그 세션의 기록을 갖고 있는 동안에만 가능하다(Claude Code는 기본 30일 뒤 지운다). **그 기한이 가까운 미수집 세션은 점검에서 경고된다.**" FR-17 — 규칙 부분이 정해진 크기를 넘으면 "그대로 넣되 점검에서 경고".
- **spine**: doctor가 세 곳에 흩어져 있다 — AD-10(연결·pgvector·버전), AD-9(spool 건수·최古 시각), AD-15(색인 설정 불일치), AD-14(끝내 실패한 규칙). **없는 것: 미수집 세션, 30일 기한 임박 경고, 주입 실패, 규칙 크기 경고, 마지막 내보내기 시각, 영어 전용 모델 검사(NFR-4).**
- **문제**: 점검은 NFR-2(조용한 실패 금지)의 단일 표면이고 Capability Map이 NFR-2를 doctor에 걸었다. 표면의 항목이 FR보다 적으면 "조용한 실패"가 되돌아온다. 특히 30일 기한은 **되돌릴 수 없는 데이터 유실 경고**다(Claude Code가 transcript를 지우면 재수집 불가). 이건 단순 목록이 아니라 drain이 transcript 폴더를 스캔해 미수집 세션의 나이를 알아야 한다는 구조 요구다 — AD-7의 "transcript 폴더 스캔"이 절반만 답한다.
- **넣어야 하는 것**: AD-9나 신설 AD에 "점검이 보이는 것" 목록을 FR-25 그대로 한 번 적고, 30일 기한 임박 경고를 drain/doctor의 책임으로 명시.

### F-11 [Medium · 모순, memlog 미설명] 미러 grep 경로가 NFR-2·FR-16의 보증 밖에 있다

- **spine**: AD-16 — 미러는 DB→파일 단방향 파생물. Capability Map "조회 (FR-12~16) | core `recall`, **미러** | AD-13, AD-15, AD-16". 구성도에 `agent -. "grep" .-> mirror`.
- **PRD**: NFR-2 — "성공으로 보이는 빈 결과나 품질이 떨어진 결과를 **표시 없이** 돌려주지 않는다." FR-16 — "**모든** 조회 결과는 출처를 가진다." FR-11 — 색인은 원문에서 다시 만들 수 있다.
- **문제**: 에이전트가 미러를 grep하는 경로는 Brain을 전혀 지나지 않는다. 따라서 `warnings`도, 출처 구조도, **미러가 최신인지에 대한 보증도 없다**(AD-16은 "그 세션의 수집만 그 파일을 쓴다"고만 하므로, 수집이 밀린 세션의 미러는 조용히 낡는다). spine이 미러를 Capability Map의 조회 수단으로 **승격**시킨 순간 NFR-2와 충돌한다.
- **memlog 대조**: memlog 54가 미러의 용도로 "아무 에이전트 grep, 사람 열람, 이후 팀 공유 출발점"을 적었지만, 그것이 FR-16/NFR-2의 보증을 우회한다는 점은 다루지 않았다.
- **넣어야 하는 것**: AD-16에 한 줄 — "미러는 사람 열람과 보조 grep용이고 조회의 보증 경로가 아니다(출처·`warnings`·최신성 보증은 SDK 조회 경로에만 있다). 각 미러 파일 머리에 마지막 갱신 시각을 적어 낡음을 드러낸다." Capability Map의 조회 행에서 미러를 보조로 표기.

### F-12 [Medium · 모순, memlog 미설명] 미러를 동기화 폴더에 두는 것이 NFR-6과 충돌한다

- **PRD**: NFR-6 — "대화 원문과 작업 로그는 **내 기계의 저장소에만 보관**된다 … 색인과 조회를 위해 조각 본문, 작업 로그, 질의가 임베딩·재순위 서비스로 **전송**된다 … **그 밖의 외부 전송은 없다.**"
- **spine**: AD-16 — "경로는 설정 한 줄(기본 `~/.second_brain/mirror/`)이고, **Brain은 그 폴더가 동기화 폴더인지 모른다.**" memlog 54 — "드라이브 동기화 폴더·Obsidian vault로 바꿔도 코드 무관."
- **문제**: 설정 한 줄로 **원문 전체가 외부로 복제되는 경로**가 열리는데 NFR-6은 그것을 금지한다. memlog 50은 "알려진 키·토큰 패턴 마스킹"을 공유 단계의 장치로 식별했고 memlog 52가 그것을 연기했으므로, 지금 미러 경로를 동기화 폴더로 바꾸면 **마스킹 없는 원문이 외부로 나간다.**
- **memlog 대조**: PRD 갱신 목록(memlog 58)의 (3)은 "§9 Postgres 하나 유지 + 미러 파생물 언급"이고 (4)는 임베딩 기본 꺼짐에 따른 NFR-6 문구 조정이다. **동기화 폴더로 인한 외부 보관은 어느 항목도 다루지 않는다.**
- **넣어야 하는 것**: AD-16이나 AD-18에 "미러 경로를 기계 밖으로 동기화되는 위치로 설정하는 것은 slice 1 범위 밖이고, 설치기·doctor가 그 경우를 경고한다(키 마스킹이 연기되었기 때문)" + PRD NFR-6 갱신(§5.2-4).

### 보조 항목 (낮은 심각도, 묶어서)

- **F-13 [Low-Medium] SDK/CLI 이름 목록이 없다.** AD-5가 "SDK 메서드·CLI 명령·MCP 도구는 같은 이름 1:1"이라는 규칙만 두고, FR-24가 요구한 13개 도구(시작 맥락, 시간 조회, 대분류, 소분류, 도구 메모 검색, 넓히기, 로그 적기, 로그 조회·수정·끄기, **워크스페이스에 넣기**, 수집 실패 조회·다시 수집, **내보내기**, 점검)의 이름을 어디에도 적지 않았다. spine에 등장하는 명령은 `context/ingest/log/recall/drain/doctor/mirror --rebuild/reindex/setup`뿐 — 내보내기·워크스페이스 편입·실패 조회·로그 수정·끄기·도구 메모 검색이 이름 없이 남았다. 또 memlog 23이 결정한 `brain connect <harness>`가 spine에서 구조 시드의 주석으로만 남았다. 1:1 규칙이 걸 대상이 비어 있으니 표 하나(SDK 메서드 ↔ CLI 명령 ↔ FR)를 넣는 것이 맞다. addendum §3의 port 목록(저장소 / 색인·검색 / 임베딩 / 재순위 / **내보내기** / Harness)도 spine에 port 목록으로 재현되지 않았다.
- **F-14 [Low-Medium] 상한(SM-C1·SM-C2)을 지키는 지점이 없다.** PRD가 "늘리려 하지 말 것"으로 못 박은 반대 지표인데(시작 맥락 최근 로그 300토큰·규칙 경고선 500토큰, 조회 결과 8,000자), spine에는 상한 개념이 없다. 수치는 spec 몫이지만 **상한을 적용하는 층**(core `context`/`recall`이 자르고 `warnings`에 코드로 남긴다)은 규약 고도다. FR-17의 "넘치면 오래된 줄부터 뺀다", "규칙은 전부 넣되 경고"도 함께 사라졌다.

- **F-16 [Low] FR-21 "선호는 시작 맥락에 들어가지 않는다"가 어디에도 없다.** addendum §7이 접은 대안("선호를 규칙에 넣기 — 항상 주입되어 시작 맥락을 잡아먹음")으로 명시한 사항이다. AD-17에 한 줄.
- **F-17 [Low] FR-22의 "끄기·적용 범위 변경"이 AD-11의 변경 경로에 없다.** AD-11은 "현재 문장 수정"과 "결정·선호 대체"만 다룬다. `rule_state` on/off와 적용 범위 변경은 문장 수정이 아니므로 어느 경로로 가는지 미정이고, FR-22는 "끈 규칙도 기록은 남는다"를 요구한다.
- **F-18 [Low] PRD §6.2의 Deferred 두 항목이 spine Deferred에 없다.** "추출·통합 엔진(실사용 채점에서 모자라면 Hindsight를 뒤에 붙인다 — addendum §3이 '같은 포트 뒤'라고 적었다)"과 "워크트리 폴더가 지워진 뒤에도 기록은 남는다(FR-4, addendum §2 `removed_at`)". 후자는 "정리 작업이 행을 지우면 안 된다"는 약한 불변이다.

## 4. (b) 코드·spec 몫 — 아키텍처 고도 아님

- 조각 크기 수치(약 1,200자, 겹침 1메시지), 벡터 top-30→재순위→top-5 (addendum §1) — AD-15의 port 뒤 파라미터.
- SM-7의 구체 수치와 `SessionStart` timeout 값 — 단, **예산을 지키는 지점**은 F-2로 (a).
- 프로젝트 없는 세션이 목록에서 "기타"로 보이는 표시(FR-4), `first_prompt`로 세션을 보이는 방식(FR-9).
- 도구 메모의 칸 구성(도구·대상·성공 여부)과 경로 검색 질의 방식(FR-2, addendum §2 전문 검색) — ERD에 `tool_notes`가 있고 AD-15의 키워드 기본이 덮는다.
- `log_entries.author_model`, `log.append`가 처음 보는 세션에 빈 세션을 먼저 만드는 것(addendum §5) — AD-8 멱등 키의 자연한 귀결.
- BMad memlog ↔ 작업 로그 종류 대응표(addendum §2 마지막 줄) — Deferred 항목의 내부 사항.

- **선행 작업: 평문 노출된 Model Studio API 키 재발급(§9)** — 운영 선행 조건. 아키텍처는 AD-18로 자리를 정했으니 (b)이지만, **spec/ticket에서 사라지기 쉬운 항목이라 ticket 단계 체크리스트로 옮겨 적어 두길 권한다**(임베딩이 기본 꺼짐이 되어 더 잊기 쉬워졌다).

## 5. PRD 갱신 목록

### 5.1 memlog가 이미 적어 둔 것 (memlog 58 "PRD 갱신 목록")

1. **§6.2 "다중 사용자, 인증 | 배제"** → 팀 공유(원문 포함)·이후 조각·단계적 도입. (§6.1 "범용 플랫폼이 아니다. 나 한 사람, 기계 한 대다."와 §2.2 Non-Users도 같은 손질 대상이다.) spine은 Deferred "팀 공유 (원문 포함)"로 이미 반영.
2. **FR-25 "Brain은 외부 의존성을 설치하지 않는다. 연결하고 검증할 뿐이다."** → 런타임은 설치하지 않음 / 설치기는 동의 후 로컬 DB를 만들 수 있음. spine AD-19 반영.
3. **§9 "저장소는 PostgreSQL 하나다. 원문, 작업 로그, 색인이 같은 곳에 있다."** → 유지 + Markdown 미러가 파생물임을 명시. spine AD-10/AD-16 반영.
4. **NFR-4 / NFR-6 / SM-3 문구** → 임베딩이 선택이고 기본 꺼짐임에 맞게 조정. spine AD-15 반영. **주의: NFR-4는 문구 조정만으로 닫히지 않는다(F-1).**

### 5.2 목록에 없는데 spine이 모순시키는 PRD 줄 (추가해야 함)

1. **FR-12 첫 Consequence** — "'어제', '지난주', '9월 30일', '작년 3월'이 **내 시간대 기준의 날짜 범위로 바뀐다**." AD-13은 그 변환을 에이전트에게 넘기고 Brain은 절대 범위만 받는다(memlog 32). PRD는 변환의 주체를 Brain으로 읽게 쓰여 있고, **SM-2("어제/지난주에 뭐 했지"의 정답률 90%)의 측정 대상도 그에 따라 바뀐다** — 에이전트의 날짜 해석 실패가 Brain의 실패로 기록되지 않도록 SM-2 정의도 손봐야 한다. §4.4 Description("날짜를 물으면 그 기간의 작업 로그를")도 같은 손질.
2. **FR-14 Consequence** — "**한국어 질의로 한국어·영어 대화를 찾는다.**" 기본 구성(키워드)에서 성립하지 않는다(F-1). "에이전트가 원어·영어 키워드를 병행해 질의한다" 또는 "임베딩을 켠 경우"로 조건을 붙여야 한다.
3. **§9 다섯째 줄** — "한국어 검색 품질은 사전 시험의 **기준선 구성(다국어 임베딩, 다국어 재순위)을 출발점으로 삼는다.**" 출발점이 키워드로 바뀌었다(memlog 55). 이 줄은 §9 Constraints라 FR보다 먼저 읽히므로 방치하면 spec 단계가 임베딩을 전제한다.
4. **NFR-6 첫 문장** — "대화 원문과 작업 로그는 **내 기계의 저장소에만 보관된다**" + 마지막 문장 "그 밖의 외부 전송은 없다." AD-16이 미러 경로를 동기화 폴더로 바꿀 수 있게 열어 두었고 키 마스킹은 연기되었다(F-12, memlog 50·52). "미러 경로는 기계 안으로 제한한다"를 NFR-6에 명시하거나, 외부 동기화를 허용하면서 마스킹 선행을 조건으로 적어야 한다.
5. **FR-5 Consequence 4** — "**Brain이나 저장소가 꺼져 있어도 Claude Code 사용은 막히지 않는다**"는 유지되지만, 같은 항의 "수집이 실패한 세션은 목록으로 확인할 수 있고 다시 수집할 수 있다"의 전제가 바뀌었다: spine에서 재수집의 원천은 **항상 Harness transcript**이고 작업 로그만 spool로 복구된다(AD-9: "transcript로 복구할 수 없는 유일한 쓰기"). PRD는 "다시 수집"의 복구 가능 범위를 구분하지 않는다 — 한 줄 명시 권장.
6. **§2.2 Non-Users** — "Claude Code 이외의 Harness로 한 작업(**구조는 막지 않지만 수집 경로가 없다**)." AD-4가 hook 없는 Harness의 수집 경로를 실제로 정의했으므로(memlog 33), slice 1의 범위 문구는 "parser를 붙이면 수집된다. slice 1이 parser를 내는 것은 Claude Code 하나"로 정확해진다.

## 6. 권고 조치 순서

1. **F-1, F-2** 먼저 — 둘 다 PRD의 측정 가능한 약속(SM-3/SM-7, NFR-4/NFR-7)을 구조가 지킬 수 없게 만든 건이고, 하나는 memlog가 "나중에 다루겠다"고 적고 지키지 않은 건이다.
2. **F-3, F-4, F-6** — 각각 한두 줄짜리 추가인데 없으면 잘못 구현될 가능성이 크고, F-6은 다음 조각에서 테이블 재설계를 부른다.
3. **F-5, F-7, F-8, F-9, F-10** — 규약/AD에 문장 추가. 분량 대비 효과가 가장 크다.
4. **F-11, F-12** — 미러의 성격(보증 밖 + 기계 안)을 AD-16에서 한 번에 정리.
5. **F-13~F-18** — spine에 표 하나(SDK↔CLI↔FR)와 AD-17·AD-11 보강.
6. PRD는 §5.1의 4건 + §5.2의 6건을 묶어 `bmad-prd update` 한 번으로.
