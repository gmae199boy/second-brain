- (decision) S1: Garmin을 second-brain 안으로 흡수해 하나의 제품으로 만든다. Garmin 비사용자는 기능을 설치/활성화하지 않아도 된다.
- (decision) S2: 주 데이터베이스는 하나의 PostgreSQL이며 OrbStack의 Docker로 실행한다. SQLite 원본/Postgres 복제 모델을 최종 제품으로 유지하지 않는다.
- (decision) S3: 지금까지 쌓인 Garmin 데이터와 이미 분석한 결과를 이전한다. 기존 데이터 이전을 생략한다는 중간 발언은 최종 정정으로 대체됐다.
- (decision) S4: 애플리케이션 설정을 DB로 옮긴다. 대상 레포의 기존 결정처럼 사용자와 함께 이동할 설정은 DB, 기계별 설정/접속 bootstrap과 비밀은 기존 분리 원칙에 맞춘다.
- (decision) S5: 독립 작업은 병렬로 실행할 수 있다. 순서가 필요한 작업은 의존성을 유지한다.
- (decision) S6: 정상적으로 작업 중인 긴 작업은 시간이 지났다는 이유만으로 취소하지 않고 관찰하며 계속 진행할 수 있어야 한다. 오류와 실제 걸림을 구분한다.
- (decision) S7: Telegram·Slack 등은 에이전트가 먼저 말을 걸고 사용자도 답하는 공통 대화 채널로 추가할 예정이다. Garmin 전용 일방향 알림에 제품 전체를 묶지 않는다.
- (decision) S8: Drive는 아직 미구현이며 임베딩 채택은 보류한다. 우선 텍스트 검색으로 진행한다.
- (decision) S9: 에이전트가 질문에 맞는 검색어/기간/자료 종류를 선택하고 검색·원문·건강 수치 조회 기능을 호출하는 방향으로 논의했다. 정확한 API 이름과 노출 표면은 아직 설계 결정이다.
- (decision) S10: 이 요청은 흡수 준비다. 실제 데이터 반입·기존 DB 스키마 변경·Docker 기동·모델 호출·메시지 발신·플러그인 배포는 이번에 수행하지 않는다.
- (decision) S11: Garmin의 구현은 대부분 존재한다. 새 제품에서 기존 계산·분석 동작을 재사용하는 것이 목표이며, TypeScript 전체 재작성은 요구하지 않았다.
- (decision) S12: 최종 이전은 원본과 기존 AI 분석을 보존해야 한다. 기존 분석을 다시 생성하는 것으로 이전 완료를 대신하지 않는다.
- (requirement) R1 (S1): Garmin을 설치하지 않은 상태에서 Brain의 기본 설치·데몬·대화 수집이 정상 동작하고 Garmin Python 의존성을 요구하지 않는다.
- (requirement) R2 (S1, S11): Garmin 확장을 설치/활성화한 사용자가 별도 Garmin 제품 설치·예약 절차 없이 연결·수집·분석을 수행할 수 있다.
- (requirement) R3 (S2, E1, E5): Brain의 대화·파일 메타데이터·설정·작업·건강 데이터는 OrbStack Docker의 단일 PostgreSQL을 주 저장소로 사용하며, 컨테이너 재생성 후 보존됨을 검증한다.
- (requirement) R4 (S4): 사용자/확장 설정은 DB에서 읽고 갱신하며 재시작 후 유지된다. 기계별 bootstrap과 비밀 저장 정책은 기존 Brain 계약과 일치한다.
- (requirement) R5 (S3, S12, E2): 실제 존재하는 모든 이전 대상의 원본·수치·기존 분석/파일을 출처 목록으로 관리하고, 이전 후 값·본문·파일 해시·관계 동등성을 검증한다.
- (requirement) R6 (S3, E2, E3): schema10/15 등 기존 소스를 먼저 원형 보관하고, legacy 데이터와 서로 다른 후보의 충돌을 자동 폐기하지 않는다.

- (requirement) R8 (S5): 대화/문서 수집과 건강 분석 등 독립 작업이 병렬로 진행되고, 건강 평가의 입력 의존성과 같은 계정의 수집 직렬성이 유지된다.
- (requirement) R9 (S6): 진행 중인 긴 작업의 소유권이 유지되고, 작업자 사망·오류·정체·사용자 취소가 구분되어 복구 또는 종료된다. 단순 임대 시간 경과로 정상 작업을 중복 실행하지 않는다.
